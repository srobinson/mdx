# ogulcancelik/herdr

Source: https://github.com/ogulcancelik/herdr · Clone inspected at v0.6.4 (commit f4f1780, 2026-05-28).

> **Landing-target correction (2026-05-29).** This review originally routed herdr's orchestration primitives onto `helioy-bus` and `warroom`. Per the locked 7-product K8s platform family (cm decision `019e327f`, 2026-05-17), `helioy-bus` is being rewritten and `warroom` is replaced by **orchestration-matters**; Nancy by **workflow-matters**. Targets below are re-pointed onto the correct products. The K8s framing makes herdr map *better*, not worse: herdr's daemon + unix-socket + verb-taxonomy model is structurally the same shape as **smd** (the session-matters daemon = API server + etcd, hosting MCP over a unix socket, with a kubectl-shaped CLI). The platform layers, for reference:
>
> | Layer | Product | K8s analogue |
> |---|---|---|
> | Persona / config / hooks | agent-matters (agm) | PodSpec |
> | IAM | identity-matters (im) | ServiceAccount + RBAC |
> | Control plane (sessions, channels, MCP, spawn API) | session-matters (sm) | API server + etcd |
> | Per-host runtime substrate (daemon + shim + launcher) | runtime-matters (rtm) | kubelet + CRI |
> | Controllers (reconcile observed vs desired) | orchestration-matters (om) | Deployment/Job controllers |
> | Choreography (DAGs, state machines) | workflow-matters (wm) | Argo |
> | Wire-level observation | transport-matters (tm) | service-mesh observability |

## 1. Stats

Rust-native terminal agent multiplexer (tmux reimagined for AI coding agents): persistent named sessions with detach/reattach, a workspace > tab > pane model, per-agent awareness detection, mouse-native splits, 18 built-in themes, SSH remote attach, and a JSON socket API for agent self-orchestration. 2,796 stars, 190 forks, created 2026-03-27 (~2 months old), last push 2026-05-28. Effectively a solo project: Ogulcan Celik authored 39 of the last 50 commits, with a bot (`kangal-bot`) and a handful of drive-by contributors. Dual-licensed **AGPL-3.0-or-later OR commercial** (LICENSE line 1; README:342). Single Rust crate (`Cargo.toml` `name = "herdr"`, edition 2021), ~101k LOC across `src/`. CI is mature for the age: 9 GitHub Actions workflows (`ci.yml`, `pr-gate.yml`, `release.yml`, `nix.yml`, contributor-approval automation), a `justfile`, a `flake.nix`, and 42 CHANGELOG release entries. Stack: ratatui 0.30 + crossterm 0.29 (TUI), portable-pty 0.9 (PTY), tokio (async), serde + serde_json + bincode (two wire formats), toml (config).

## 2. Grade

**B / B+.** Sits at graphify (B) trending toward superpowers (B+). The agent-orchestration plumbing (dual-socket session model, JSON-RPC API, confidence-arbitrated detection) is genuinely well-factored and directly informs the agent-platform control plane (session-matters / orchestration-matters). Held back from A− by: AGPL copyleft (caps reuse to ideas), several files well over Helioy's 700-line limit (`server/headless.rs` 4,965; `app/actions.rs` 3,927; `app/mod.rs` 3,391; `detect.rs` 2,989; `app/state.rs` 1,643), and a TUI rendering surface that transfers nothing to an Electron chassis. Call it **B+** specifically for the control plane (session-matters / orchestration-matters) — the socket + detection layers are the best of the three cousins reviewed; **B** as a littleorgans chassis reference (IA is portable but the surface is wrong).

## 3. Primitives that transfer

### Layer 1 — Interaction / information architecture (portable to any shell: Electron/Tauri/web)

1. **Workspace > tab > pane hierarchy as a serializable graph.** `src/persist/snapshot.rs:16-89` — `SessionSnapshot { workspaces, active, selected, sidebar_width, sidebar_section_split, collapsed_space_keys }` → `WorkspaceSnapshot { id, custom_name, identity_cwd, worktree_space, tabs, active_tab }` → `TabSnapshot { custom_name, layout, panes, zoomed, focused, root_pane }`. A workspace is keyed by `identity_cwd` (the repo dir), not an arbitrary id — workspace identity follows the working directory. **Landing target: littleorgans** frontend IA model + **session-matters** `workspace` field (the K8s Namespace on a session). Workspace-identity-follows-repo-dir IS the namespace model; the pane = a runtime instance owned by **runtime-matters**.

2. **Semantic-token theme palette.** `src/app/state.rs:6-39` — `Palette` is a flat struct of named semantic tokens: `accent, panel_bg, surface0, surface1, surface_dim, overlay0, overlay1, text, subtext0, mauve, green, yellow, red, blue, teal, peach`. Each of 18 built-in themes is a constructor returning RGB triples (`catppuccin()` at :43, `catppuccin_latte()` at :65, `tokyo_night()`, `dracula()`, `nord()`, `gruvbox()`, `solarized()` …). Theme resolution is name-normalized with aliases (`app/state.rs:479` — `"catppuccin-mocha"`, `"latte"|"light"`, `"tokyonight"`). User config is `name` + `custom` token override (`src/config/theme.rs:16-26` `ThemeConfig { name, custom }`, `CustomThemeColors`), and `parse_color` (`config/theme.rs:47`) accepts hex, named ANSI, and `reset`. This is a design-token system in everything but name. **Landing target: littleorgans `design.md` / design-token approach** — the `surface0/1/dim` + `overlay0/1` + `subtext0` naming is a ready-made token vocabulary; the `name`-plus-`custom`-override config is the exact shape a themeable Electron app wants. Unaffected by the bus/warroom deprecation — this is a pure frontend lift.

3. **Confidence-tagged status surfacing.** `src/detect.rs:21-35` — `AgentDetection { state, visible_blocker, visible_idle, visible_working }` carries not just the state but *why we believe it* (is the blocking UI actually on screen right now). The sidebar renders status per pane (`src/ui/sidebar.rs`). **Landing target: orchestration-matters** (controller-side status) surfaced in **littleorgans** agent-status UI.

### Layer 2 — Agent-orchestration plumbing (re-pointed onto the platform family)

4. **JSON-RPC-shaped Unix-socket control plane.** `src/api/schema.rs:5-105` — `Request { id, #[serde(flatten)] method }` where `Method` is `#[serde(tag = "method", content = "params")]` over ~45 verbs: `workspace.create/list/focus/rename/close`, `tab.*`, `pane.split/send_text/send_keys/send_input/read/close`, `agent.list/get/read/send/start`, `worktree.*`, `events.subscribe/wait`, `pane.wait_for_output`, `integration.install/uninstall`. Transport is line-delimited JSON over a `UnixListener` (`src/api/server.rs:72`, `serde_json::from_str::<Request>` at :149, `write_json_line` at :451), with a 2MB frame guard and socket-permission restriction (`restrict_socket_permissions`, `SOCKET_PERMISSION_MODE`). **This is a near-exact analogue of the session-matters daemon (smd) contract** — invariant #5 of the platform family is "daemons ARE MCP servers," and herdr is a daemon hosting a verb API over a unix socket. The `workspace.*/tab.*/pane.*/agent.*` namespacing maps onto the kubectl-shaped `sm get/delete agent X` CLI. Landing target: **session-matters** (envelope + verb taxonomy). Weigh herdr's flat verb enum against the A2A-envelope migration direction — herdr's enum is simpler and worth the comparison.

5. **Dual-socket separation: control plane vs render plane.** `src/server/socket_paths.rs` + `src/session.rs:135-150` — a JSON API socket (`herdr.sock`, human/agent orchestration) and a *separate* client protocol socket (`herdr-client.sock`) carrying terminal frames. The render socket uses a different wire format entirely: length-prefixed bincode binary frames (`src/protocol/wire.rs:466-548` — `[u32LE length][bincode payload]`, `write_message`/`read_message`, `MAX_FRAME_SIZE` 2MB). The lesson: **orchestration and high-bandwidth streaming should not share a wire format.** JSON for control (debuggable, agent-writable); binary for the hot path. Landing target: **session-matters** keeps its control socket clean JSON; the streaming/observation axis belongs to **transport-matters** (the platform's independent wire-observation product). Do not base64-stuff a stream into the control envelope.

6. **Agent-awareness detection = per-agent screen-scrape heuristics, arbitrated against hook signals.** `src/detect.rs` is the centerpiece. `detect_agent(agent, screen_content)` (`:166`) dispatches to one hand-written detector per agent (`detect_claude` :222, `detect_codex` :251, `detect_gemini` :276, `detect_cursor` :303 … 16 agents total at the `Agent` enum :39-56). Each detector pattern-matches the *terminal tail* (bottom-of-buffer text) for that agent's known UI chrome — e.g. Claude looks for its prompt-box border + blocked-prompt strings (`has_claude_blocked_prompt`); Codex matches `"press enter to confirm or esc to cancel"`, `"[y/n]"` (`:255-261`); Gemini matches box-drawing `"│ Apply this change"` (`:285`). States are `Idle | Working | Blocked | Unknown` (`:8-17`). Critically, **screen detection is reconciled with agent-installed hooks**: agents call back via `pane.report_agent` / `pane.clear_agent_authority` (`api/schema.rs:85-91`), and the screen-derived `visible_blocker/visible_idle/visible_working` flags arbitrate against that hook-reported authority (`src/pane.rs:377` — `let visible_blocker = detection.visible_blocker && new_state == AgentState::Blocked;`). The doc comments at `detect.rs:23-34` spell out the arbitration: visible on-screen chrome can override a stale hook idle-report, and a missed interrupt event is recovered by `visible_idle`. Landing target: **runtime-matters** owns the semantic-state probe (it sits ON TOP of rtm's three-layer liveness — shim waitpid → kqueue → probe sweep — which answers "is it alive"; herdr's detection answers "is it blocked/working/done"); the classification feeds **orchestration-matters** controllers that reconcile observed vs desired state. This is the clean K8s mapping: kubelet reports pod status, controllers act on it.

7. **Per-agent integration/hook installer.** `src/integration/mod.rs:44-250` — per-agent install path structs (`ClaudeInstallPaths`, `CodexInstallPaths { hook_path, hooks_path, config_path }`, `OpenCodeInstallPaths`, `HermesInstallPaths`, `QodercliInstallPaths`) and a single `install_target(agent)` dispatcher (`:177`) that writes each agent's hook into its own config dir and reports what it did. `IntegrationStatus { installed_version, kind }` + `IntegrationRecommendation::needs_install()` (`:114`) version the installed hook so it can self-upgrade. This is the same "declarative per-agent adapter matrix" pattern flagged in the cmux review (`AgentHookDef`), but in Rust and keyed to hook-file installation. Landing target: **split** — config/hook provisioning (CLAUDE_CONFIG_DIR, skills, role configs) is **agent-matters**; the per-runtime launch/wrap adapter (claude, codex) is **runtime-matters**' RuntimeLauncher. One declarative table of {agent, config_dir, hook_file, hook_format, events, version} should feed both install and detection.

8. **Event API: pull (`wait`) and subscribe, split deliberately.** `src/api/schema.rs:421-489` — `EventsWait { match_event, timeout_ms }` blocks for one matching event with a timeout (pull/one-shot); `EventsSubscribe { subscriptions: Vec<Subscription> }` (`:421`) streams a typed event set (`Subscription` is `#[serde(tag="type")]` over `workspace.created`, `pane.agent_detected`, `pane.output_matched { pane_id, match, strip_ansi }`, `pane.agent_status_changed { agent_status }` …). `PaneWaitForOutput { pane_id, match, timeout_ms, strip_ansi }` (`:482`) is a targeted pull. **This validates the rtm "pull now, subscribe later" decision** ([[project_rtm_event_contract_pull_then_subscribe]]): herdr ships both, with `wait` as the simple agent-facing primitive and `subscribe` as the streaming superset. Landing target: **session-matters** channels (mail + nudge + events) and the existing **runtime-matters** event contract.

### Layer 2 divergence — the sqlite question (correction to the original review)

The original review framed herdr's persistence as evidence that "file-per-session JSON suffices, contrast ntm's SQLite." That framing must not leak into Helioy's storage decision. herdr's model: each named session is a directory `config_dir/sessions/<name>/` holding `herdr.sock` + `herdr-client.sock` (`src/session.rs:127-150`); `list_sessions()` (`:153`) just reads the dir; state is a **versioned JSON snapshot** (`persist/snapshot.rs:12` `SNAPSHOT_VERSION: u32 = 3`) with `#[serde(default)]` forward-compat on every field and a `LegacyWorkspaceSnapshot` (`:65`) migration path. No SQLite.

But Helioy has **locked sqlite for both smd and rtmd** (platform invariant set): identity-matters' audit table lives in the sm-store sqlite, and session-matters owns first-class **labels and selectors** that need a queryable store (`sm get agents -l workspace=foo`). herdr is a single-user multiplexer with a handful of named sessions; it never queries across sessions by label, so a JSON file is enough. Helioy is a control plane with selector/label/audit semantics. So herdr confirms the *lower bound* (versioned-JSON forward-compat migration is a sound pattern, worth borrowing for snapshot schema evolution) but is **not** evidence to reopen the sqlite decision. ntm's sqlite-WAL backbone is the closer analogue to Helioy's choice.

### Layer 3 — Distribution / product surface

9. **`SKILL.md` ships in-repo as the agent's self-control manual.** `SKILL.md` (frontmatter `name: herdr`) instructs an agent running *inside* herdr (gated on `HERDR_ENV=1`) to drive the multiplexer via CLI verbs that hit the socket. The product is designed for the agent to be a first-class operator of its own container. Landing target: the **session-matters `sm` CLI** should ship a SKILL.md so agents can self-orchestrate the shell; littleorgans surfaces it.

10. **Single-binary, no-deps packaging with `just` + `nix` build ergonomics.** `justfile` (test/lint/ci/check/build/website-build/release recipes) + `flake.nix` (`buildRustPackage`, devShell, `nix run`) + `website/install.sh` + `website/latest.json` self-hosted update channel. `cargo install` / single static binary, no runtime deps. Landing target: Helioy distribution polish for the Rust daemons (smd/rtmd are Rust 2024) — contrast littleorgans' Electron three-app baseline (see §4).

11. **`AGENTS.md` as the contributor/agent contract** (118 lines) plus contributor-approval CI automation (`approve-contributor.yml`, `label-intends-to-pr.yml`) and a self-hosted docs site (`website/` Astro, `docs/next/`, `herdr.dev/docs/socket-api/`). 42 releases in ~2 months is an aggressive, polished cadence for a solo project.

## 4. Does NOT transfer

1. **The entire TUI rendering layer.** ratatui/crossterm cell-buffer rendering (`src/ui/*`, `src/protocol/render_ansi.rs`, `src/protocol/wire.rs` `FrameData`/`CellData` 1,560 LOC, `src/kitty_graphics.rs`, the bincode frame protocol) is terminal-cell-grid output. An Electron/Tauri GUI renders DOM/canvas; none of this code or its abstractions carry over. This is the seam: herdr is valuable *despite* its rendering layer, not because of it.
2. **AGPL-3.0-or-later copyleft.** littleorgans ships MIT public mirrors under the `littleorgans` org. Copying any herdr source would force AGPL on the consumer. **Borrow ideas and architecture; never code.** This caps the verdict at borrow/inspiration regardless of technical fit.
3. **PTY/process-supervision internals** (`src/pane/terminal.rs` 2,590 LOC, `portable-pty`, foreground-job detection in `src/platform/macos.rs`) — a terminal multiplexer's job, not a chassis's.
4. **No-sqlite persistence.** Helioy chose sqlite for smd/rtmd deliberately (audit + selectors/labels). See the Layer 2 divergence above.
5. **Monolithic files.** `server/headless.rs` (4,965), `app/actions.rs` (3,927), `app/mod.rs` (3,391), `detect.rs` (2,989), `pane.rs` (2,868). All far past Helioy's 700-line hard limit. Read for shape; do not adopt structure.
6. **Single-Rust-binary architecture diverges from the locked littleorgans baseline** (t3code three-app Effect-based Electron monorepo `apps/{desktop,server,web}`). See §7.

## 5. Verdict

**Borrow-primitives (session-matters / orchestration-matters / runtime-matters / agent-matters) + inspiration-only (littleorgans chassis).** The socket-API verb taxonomy, dual-socket control/render split, confidence-arbitrated per-agent detection, and pull-then-subscribe event contract are the strongest agent-orchestration references of the three cousins (cmux, ntm, herdr); reimplement them clean in Helioy's Rust stack. The TUI surface and AGPL cap any chassis reuse to inspiration.

## 6. Why

herdr and the Helioy platform converge on the same problem from opposite ends of the rendering spectrum. herdr is a terminal multiplexer where the pane is the unit of agency; Helioy is a K8s-faithful control plane where a typed runtime session is the unit of agency, rendered by littleorgans. Strip away rendering and both need the identical middle layer: a control protocol an agent can speak, a session model that survives detach, a way to know whether each agent is blocked/working/done, and a way to install hooks into a dozen heterogeneous coding agents. herdr's version of that middle layer is unusually clean for a two-month-old solo project — it deliberately separates the JSON control plane (agent-writable, debuggable) from the binary render plane, it tags every detected state with on-screen evidence so it can arbitrate stale hook reports, and it ships both a one-shot `wait` and a streaming `subscribe` exactly as Helioy's rtm contract already plans to. herdr's daemon-hosts-a-verb-socket shape is the same shape as smd. The cost of adopting it wholesale is the 60k+ LOC of terminal rendering and PTY supervision that would ride along, plus AGPL contamination. So the move is to lift the protocol shapes and the detection-arbitration idea, not the binary.

## 7. How to apply

1. **session-matters envelope + verb taxonomy.** Read `src/api/schema.rs:5-105` when shaping the smd message contract. The `Request { id, #[serde(flatten)] method }` with `#[serde(tag="method", content="params")]` is a clean JSON-RPC variant; the `workspace.*/tab.*/pane.*/agent.*/events.*` namespacing maps onto the kubectl-shaped `sm get/delete/spawn` verbs. Weigh herdr's flat verb enum against the A2A-envelope migration direction — herdr's enum is simpler and worth the comparison.
2. **Keep control JSON, give streaming its own channel.** Adopt herdr's dual-socket lesson (`session.rs:135-150`): smd's control socket stays JSON; route high-bandwidth streaming/observation through **transport-matters** with its own framed protocol (`protocol/wire.rs` length-prefix pattern) rather than base64-stuffing JSON.
3. **orchestration-matters status reconciliation.** Port the *idea* of `src/detect.rs` `AgentDetection { state, visible_blocker, visible_idle, visible_working }`: classify each session as blocked/working/done, tag the classification with its evidence source, and reconcile a hook signal against a probe. runtime-matters runs the probe; orchestration-matters' controllers consume the reconciled state. Prefer hook callbacks (`pane.report_agent`) as authority, fall back to output-scrape, and let on-screen evidence override a stale idle report (`pane.rs:377`).
4. **agent-matters + runtime-matters adapter catalog.** Model the adapter on `src/integration/mod.rs` install-path structs + `install_target` dispatcher + versioned `IntegrationStatus`. Combine with the cmux `AgentHookDef` matrix ([[manaflow-ai/cmux review]]): one declarative table of {agent, config_dir, hook_file, hook_format, events, version} — agent-matters owns the config/hook provisioning, runtime-matters owns the launch adapter, and both read the same table.
5. **littleorgans design tokens.** Lift the `Palette` token vocabulary (`app/state.rs:6-39`: `surface0/1/dim`, `overlay0/1`, `subtext0`, semantic accent colors) and the `name`+`custom`-override config (`config/theme.rs:16`) into littleorgans' design.md. Ship the same 18 named themes as CSS-variable token sets; let users pick a name and override individual tokens. This is the one step the original "frontend Electron/Tauri" framing pointed at directly.
6. **rtm event contract — herdr is corroboration, not a new decision.** `EventsWait`(timeout_ms) + `EventsSubscribe`(typed Subscription set) confirms [[project_rtm_event_contract_pull_then_subscribe]]. Ship `wait` first as the agent-facing pull primitive; land `subscribe` as a strict superset.
7. **Borrow the versioned-snapshot migration pattern, not the no-sqlite model.** `persist/snapshot.rs` `SNAPSHOT_VERSION` + `#[serde(default)]` + `LegacyWorkspaceSnapshot` is a clean schema-evolution pattern worth lifting into the sm-store/rtm-store row payloads. Keep sqlite as the locked storage engine (see §4.4).
8. **Ship a SKILL.md for the `sm` CLI.** Mirror herdr's `SKILL.md` + `HERDR_ENV=1` gate so an agent inside a session can self-orchestrate via the `sm` verbs.
