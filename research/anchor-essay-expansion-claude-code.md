## Notes

### Source quality and confidence flags

**High-confidence primary sources used:**
- `code.claude.com/docs/en/*` — official Claude Code documentation. Domain redirected from `docs.anthropic.com` in early 2026; canonical now.
- `platform.claude.com/docs/en/*` — official Anthropic API documentation, including the prompt-caching and tool-search specs.
- `claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything` — Anthropic-authored engineering blog post about Claude Code's caching strategy.
- `github.com/anthropics/claude-code` — Anthropic-owned issue tracker. Repository is public for issues only; the source itself is not open-source.
- `github.com/Piebald-AI/claude-code-system-prompts` — third-party repo that mechanically extracts strings from the published `@anthropic-ai/claude-code` npm artifact. Methodology is reproducible; updates within minutes of each release. v2.1.126 covered as of 2026-04-30. Treated as **medium-high** because the extraction is automated against the canonical npm artifact, but it is not authored by Anthropic.

**Notable: Claude Code is not open-source.** Per Piebald's README ("110+ strings that are constantly changing and moving within a very large minified JS file"), the strings are extracted from compiled JavaScript. The `anthropics/claude-code` GitHub repo hosts issues, changelog, and release notes only — no source code. This is the highest-quality non-source-code primary reference available.

### Specific gaps and ambiguities

- **Exact `MAX_LINES_CONSTANT`**: docs and the extracted Read tool description both use the placeholder `${MAX_LINES_CONSTANT}`. Community references (issues #6910, #14888) and the title of issue #40357 indicate the constant is **2000** for the CLI and **10,000 tokens** as a separate cap. The 25,000-token cap reported in some practitioner sources (cited above) may apply at a different layer. Worth verifying with a live capture before publishing a hard number.
- **Env block exact contents**: Anthropic docs describe categorically what's included ("working directory and environment", "Environment context: Automatic"), but no public Anthropic doc enumerates the field list. The set used in this session (Working directory, Is directory a git repo, Platform, Shell, OS Version, model name, today's date) is reproducible by inspection of any active Claude Code session and is the canonical list across all observed captures, but cite this as **direct observation in current session** plus documentation that env context is included, not a single docs URL with the full list.
- **First-turn token deltas for `ENABLE_TOOL_SEARCH=false` vs default**: the four-figure delta the essay claims is consistent with the documented "50 tools = 10-20K tokens" and "55K tokens for a typical multi-server MCP setup" figures, but the exact delta depends on the user's installed servers. The author should publish the count from his own mitmdump capture rather than cite a generic figure.
- **`<system-reminder>` enumeration**: Piebald lists ~40 system reminders. The full inventory is in the repo's `system-prompts/system-reminder-*.md` files. The most relevant for the essay are `system-reminder-thinking-frequency-tuning.md`, `system-reminder-memory-file-contents.md`, `system-reminder-file-truncated.md`, `system-reminder-file-shorter-than-offset.md`, `system-reminder-previously-invoked-skills.md`.
- **MCP descriptor location in the request body**: the docs confirm tool naming and behavior, but do not publish the wire-level placement of MCP descriptors. Practitioner captures (kirshatrov.com, nerdleveltech.com) confirm tools array contains the full schema, but neither captures a request with deferred-tool MCP servers to verify the inline `tool_reference` block placement that the platform docs describe. This is the cleanest gap to fill with a personal mitmdump capture.

### Recommended live-capture steps to close gaps

1. `mitmdump` capture of a fresh Claude Code session with no MCP servers configured, then with one MCP server, then with `ENABLE_TOOL_SEARCH=false` set: produces concrete token deltas for the essay's "four-figure" claim.
2. `claude --print "read /tmp/empty.txt"` with the file existing but empty: captures the empty-file `<system-reminder>` shape.
3. Read of a >2000-line file: captures the truncation `<system-reminder>` and the `cat -n`-formatted output block, sized for the essay's "what the tool result looks like" segment.
