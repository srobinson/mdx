# iterate/iterate

## 1. Stats

169 stars, 7 months old (created 2025-09-15, last push 2026-05-15), 17 unique authors across 1150 commits, active CI with 24 workflow files (deploy, integration, sandbox, spec, dependabot, claude-assistant, autofix). License is **AGPL-3.0-only** at the repo root, with **Apache-2.0** carved out for the `packages/iterate` CLI. Tagline: "The most hackable AI agent." TypeScript-dominant (7.3 MB), with a Cloudflare Workers control plane plus a self-hostable agent daemon running on Fly.io or Docker.

## 2. Tech stack and file-system layout

Stuart's "tidy codebase" read holds, with caveats around a few oversized files in the core kernel.

Runtime and platform: Cloudflare Workers + Durable Objects (control plane), Fly.io + Docker (agent daemons), PlanetScale Postgres, pgmq for outbox, Clerk for auth + MCP OAuth, Doppler for secrets, Alchemy for Cloudflare IaC, Depot for fast Docker builds. Frontend is TanStack Start + Router + Query + shadcn. Backend uses oRPC over HTTP/OpenAPI. Tests are Vitest + Playwright. Lint/format is oxlint + oxfmt (Oxc, no ESLint/Prettier). Build/dev is pnpm catalogs with `minimumReleaseAge: 1440` (24h supply-chain hold).

Top-level shape:

```
apps/             ~20 apps: os (legacy), os2 (new), daemon, agents, events, semaphore, iterate-com
  os/{app,backend} React + Cloudflare Worker, ~28K LoC
  os2/src         TanStack Start + Workers, src/domains/* DDD-style
  daemon/         Agent runtime on machines, oRPC routers (slack, github, webchat, pty)
packages/
  shared/         Kernel: streams, stream-processors, codemode, durable-object-utils, alchemy helpers
  iterate/        Apache-2.0 CLI, locally-delegating
  pidnap/         Process supervisor (pidnap.config.ts)
  ui/             Shared UI
sandbox/          Sandbox image + provider abstraction (Fly primary, Daytona optional)
spec/             Playwright "specs" not "e2e" with custom plugin system
docs/             Architecture + ADRs + operator cheatsheets
tasks/            Markdown task files with state/priority/size/dependsOn frontmatter
.agents/skills/   Skills for agent-tools (claude-code, opencode)
.opencode/skills/ Skill set for opencode
.cursor/skills/   Cursor skills
.github/
  workflows/      24 YAMLs, all generated
  ts-workflows/   TypeScript source for the YAMLs (cli.ts, 245 LoC)
repo-templates/   Templated repos for new agent workspaces
```

Three signals of craft: (1) `AGENTS.md` is the canonical agent doc, `CLAUDE.md` is a symlink to it; (2) `CONTEXT.md` is a 162-line **glossary with "Avoid" rules** that codifies Ubiquitous Language; (3) GitHub Actions YAMLs are generated from TypeScript with a typed workflow DSL, and PRs to `.yml` files would lose. File-size discipline is mostly OK, with concentrated overflows in the stream-processor kernel (944 + 1361 LoC test) and a few oRPC routers and integration files (1300, 1116, 1091, 1036 LoC).

## 3. Grade

**A-.** Above notebooklm-py and mngr in scale and infrastructure breadth, tied with fallow-rs/fallow on overall craft, below A only because of the AGPL boundary and a handful of oversized files in the core kernel. Distinct from B+ peers (superpowers, manaflow-ai/cmux) by being a real production system with versioned deployments, depot caching, dependabot, ADRs, and a 17-author commit history.

## 4. Primitives that transfer

1. **Generated CI YAML from typed TypeScript DSL**
   `/tmp/gh-research/iterate-iterate/.github/ts-workflows/cli.ts:1-50` plus `.github/workflows/ci.yml:1` ("this file is generated by ci.ts, do not edit it manually"). Uses `@jlarky/gha-ts/workflow-types` + Zod + `trpc-cli`. Lands in **helioy-plugins** / Helioy repo CI. Useful for runtime-matters where workflow generation could be a primitive too.

2. **Multi-target skill install with one source of truth**
   `package.json:17`: `"skills:sync": "npx skills add . --skill '*' -a claude-code -a opencode -g -y"`. The repo keeps `.agents/skills/`, `.opencode/skills/`, `.cursor/skills/` populated through the upstream `skills` package (agentskills.io). Skills carry `publish: false` to gate export. Lands directly in **runtime-matters** as the cross-tool skill distribution primitive (Claude Code, OpenCode, Pi, Copilot, Goose).

3. **CLI that delegates to local source when run inside the repo**
   `/tmp/gh-research/iterate-iterate/packages/iterate/bin/iterate.js:30-70`. Walks up from cwd looking for `pnpm-workspace.yaml`, then re-imports the local TS source. Means global `iterate` CLI users always run the version pinned to whatever repo they're standing in. Drop-in pattern for any Helioy CLI (**runtime-matters**, **transport-matters** CLI shim).

4. **CONTEXT.md as Ubiquitous Language with Avoid rules**
   `/tmp/gh-research/iterate-iterate/CONTEXT.md:1-162`. Each term: definition + `_Avoid_: synonyms`. Followed by Relationships, Example dialogue, and Flagged ambiguities. This is Eric Evans' Ubiquitous Language operationalized. Lands directly in Helioy's open Ubiquitous Language thread; it is the missing template.

5. **Playwright spinner-waiter + llm-recover plugins**
   `/tmp/gh-research/iterate-iterate/spec/plugins/spinner-waiter.ts:1-172` and `spec/plugins/llm-recover.ts:1-444`. Spinner-waiter inverts the timeout problem: short default wait, fall back to looking for loading UI; if neither, fail fast. Llm-recover lets a model patch a flaky spec mid-run. **transport-matters** can borrow the failure-path observability framing.

6. **Durable Object mixins as a primitive family**
   `/tmp/gh-research/iterate-iterate/packages/shared/src/durable-object-utils/mixins/` lists `with-stream-processor-runner.ts`, `with-lifecycle-hooks.ts`, `with-scheduler.ts`, `with-multiplexed-alarms.ts`, etc. Type-tested with dedicated `*.type.test.ts` files and a separate `vitest.type.config.ts`. Pattern (mixin family + type tests) lands in **fmm** primitive families and **helix** if helix grows persistent stateful units.

7. **pnpm catalogs + `minimumReleaseAge` supply-chain hardening**
   `pnpm-workspace.yaml:31-74`. Catalogs centralize Cloudflare version pinning across the monorepo; `minimumReleaseAge: 1440` blocks deps less than 24h old (with an explicit exclude list for trusted publishers). Lands in **helioy-plugins** monorepo hygiene, especially as packages multiply.

8. **Append-only event streams + processor contracts**
   `/tmp/gh-research/iterate-iterate/packages/shared/src/stream-processors/types.ts:36-46` (EventDefinition + EventCatalog with Zod schemas). Pair of `contract.ts` + `implementation.ts` files per processor (agent, agent-chat, slack, slack-agent). Lands in **helix** if it adopts event-stream semantics, and in **attention-matters** for the stored-state + reducer pattern.

9. **Tasks as filesystem markdown with state frontmatter**
   `tasks/install-agent-skills-to-home-directory.md:1-10` shows `state, tags, priority, certainty, size, difficulty`. Coexists with Linear. Lands in Helioy as an alternative to Linear for repo-local tasks, or as inspiration for the **knowledge-matters** structured-doc model.

## 5. Does NOT transfer

1. **AGPL-3.0-only on the monorepo.** Any vendoring of `apps/*` or `packages/shared/*` source into Helioy triggers AGPL on the consuming work. Only `packages/iterate` (Apache-2.0) is safe to vendor. For everything else, **read and reimplement**, do not copy.
2. **Cloudflare Workers + Durable Objects coupling.** Helioy is local-first/Mac-first. The stream-processor kernel, mixins, and oRPC plumbing assume Workers and DO are runtime substrates. Take the *shape* (event streams, mixin pattern) and reimplement on a local substrate.
3. **Doppler + Alchemy + Depot + Fly + PlanetScale stack.** Specific to iterate's deployment topology. Skip wholesale.
4. **Clerk + organizations + MCP OAuth.** Helioy has no organization model and no multi-tenant story to justify Clerk.
5. **The Slack / Webchat / GitHub agent runtime.** Belongs to iterate's product surface (control-plane + machine agent for end users). Out of scope for Helioy.
6. **The sandbox image pipeline.** Helioy does not run sandboxed agent VMs; this entire layer is orthogonal.
7. **A few oversized files (1100-1361 LoC).** Notable in `apps/os/backend/integrations/github/github.ts`, `apps/os/backend/orpc/routers/project.ts`, `packages/shared/src/streams/stream-durable-object.ts`. Stuart's 700 LoC threshold would mandate refactor; iterate has not done so for the kernel. Not a primitive to transfer.

## 6. Verdict per Helioy target

- **runtime-matters** — **borrow-primitives**: skills:sync multi-target install (primitive 2), CLI local delegation (primitive 3), `publish: false` skill gate.
- **helix** — **inspiration**: event-stream processor contracts (primitive 8) and DO mixin pattern (primitive 6). Reimplement, do not vendor.
- **transport-matters** — **inspiration**: spinner-waiter / llm-recover failure-path framing (primitive 5).
- **fmm** — **inspiration**: durable-object-utils/mixins as a primitive family with type tests; CONTEXT.md as a glossary fmm could surface.
- **context-matters** — **inspiration**: CONTEXT.md Ubiquitous Language pattern (primitive 4) directly informs the cm structured-glossary story.
- **knowledge-matters** — **inspiration**: tasks/ markdown + AGENTS.md hierarchy (per-app AGENTS.md, symlinked CLAUDE.md) as a docs layout primitive.
- **attention-matters** — **skip**: nothing aligned; iterate's reducer/state pattern is Worker-bound.
- **littleorgans** — **skip**: different chassis entirely.

Cross-cutting: **inspiration** for Helioy repo hygiene (TS-generated workflows, pnpm catalogs, `minimumReleaseAge`, oxlint+oxfmt).

## 7. Why

Iterate is what a well-funded team builds when they take "hackable agent" seriously: a control plane + self-hostable daemon, append-only event streams, processor contracts, MCP-first OAuth, multi-target skill distribution, and a CONTEXT.md that operationalizes Ubiquitous Language. The infrastructure is heavy enough that wholesale adoption would distort Helioy, and the AGPL boundary makes vendoring source unsafe. The transfer story is mostly *primitives* (skills:sync, CLI local delegation, CONTEXT.md format, TS-generated workflows) plus *inspiration* for the kernel shape (event streams, DO mixins). Stuart's "tidy" read holds at the repo-hygiene layer (workflows, catalogs, frontmatter discipline, oxlint, husky, dependabot, lint-staged) and at the docs layer (AGENTS.md per app, CONTEXT.md glossary, ADRs in `docs/adr/`). It strains in the kernel where a few files push 1000-1361 LoC, which is precisely where Helioy's 700 LoC threshold should diverge from iterate's practice.

## 8. How to apply

1. **CONTEXT.md template for Helioy.** Lift the format directly: Term + `_Avoid_:` line, then Relationships, Example dialogue, Flagged ambiguities. Seed it with the Helioy ubiquitous-language workstream that is currently open. This is the single highest-leverage primitive in the repo.
2. **runtime-matters skills:sync.** Adopt the upstream `skills` package and its `npx skills add . --skill '*' -a <target>` pattern as the canonical multi-target install for runtime-matters. Confirm against the existing `agentskills.io` spec.
3. **CLI local delegation in runtime-matters and any future Helioy CLI.** Port `packages/iterate/bin/iterate.js`'s findUp + `pnpm-workspace.yaml` walk-up trick. Apache-2.0 so it can be vendored.
4. **TS-generated workflows.** Replace any handwritten `.github/workflows/*.yml` in Helioy with a `ts-workflows/cli.ts` generator using `@jlarky/gha-ts/workflow-types` + Zod.
5. **pnpm catalogs + `minimumReleaseAge`.** Apply to helioy-plugins as it accumulates dependencies. Carry an explicit exclude list only for trusted publishers Helioy actively follows.
6. **AGENTS.md per package, CLAUDE.md as symlink.** Adopt as a convention across Helioy components so every package has a local AGENTS.md that the harness picks up.
7. **For helix specifically:** read `packages/shared/src/stream-processors/{types.ts,stream-processor.ts}` and the `agent-chat/{contract,implementation}.ts` pair, then design helix's loop in those shapes without copying source. Note where iterate violated the 700-LoC line so helix does not.
