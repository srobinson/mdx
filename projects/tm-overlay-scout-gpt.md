## Verdict

Canvas requests already traverse the complete override pipeline. Canvas does not arm a breakpoint, and no launch kind check disables `run_pipeline`. The current Canvas launch path supplies no override carrier and makes no run scoped store write, leaving its scope empty unless another client calls the override API.

The preserved WIP identifies the correct population seam: `api/src/transport_matters/addon_runtime.py:load_capture_runtime`. It snapshots confirmed browser overlays at launch, filters project scope after canonical worktree resolution, carries raw overrides through launch fields, seeds the run root scope before traffic, and strips the transient carrier from the durable binding.

The required fail open behavior is absent. Exceptions in `api/src/transport_matters/request_pipeline.py:run_pipeline` return the original request. Ordinary target misses return `applied=false`, while other operations continue mutating the request. A focused production seam probe combined a missing `system:99` target with a valid `tool:mcp_bash` target and produced a modified request with one failed and one applied audit entry. Partial output is reachable.

There is no captured turn replay through the override pipeline. The only reapplication route, `api/src/transport_matters/api/v1/breakpoint_routes.py:re_audit_flow`, requires a live paused flow. Historical exchange reads and Codex derived replay helpers do not call `apply_overrides` or send a reconstructed request upstream.

## WIP versus the three first run slices

Commit `23a49430` remains useful as a launch transport and population proof. The three current first run slices are `7568d5b8`, `4748b4b4`, and `cba4d4df`. Their source diff adds first prompt delivery, correct exchange selection, stream driven landing, and first run Canvas presentation. They introduce no `LaunchOverlay`, `initial_overrides`, Canvas override API call, or store population.

The two branches overlap in `www/packages/canvas/src/model/capturedRunStore.ts`, `www/packages/core/src/transport.ts`, and the transport test. A read only `git merge-tree` predicts textual conflicts in the transport option fields and adjacent tests. The functionality is additive. It has not been superseded.

The WIP should be treated as salvage rather than accepted intact. It proves the existing owner path from launch intent to addon startup. It does not provide TM authored defaults, whole overlay fail open semantics, a content guard, replay evaluation, explicit manual precedence, or retained overlay identity. Its flattened carrier prevents the current audit from answering which named and versioned overlay changed a block.

## Smallest safe content win

The smallest useful default is one TM authored operation that disables the exact `Artifact` tool for ordinary coding launches. The retained 22 tool request measures that definition at 10,674 characters through production `tool_chars`, which is 20.3 percent of the 52,667 character tool payload. The character saving is exact for that request. The cache write token reduction is unmeasured.

This candidate fits the current owners. `tool_toggle` already targets a tool by exact name, `OverrideStore` already lets a later manual value reenable the same key, and the WIP already carries an initial snapshot to `load_capture_runtime`. A one operation overlay also avoids current partial application between sibling operations.

Safety requires the operation to carry and validate a fingerprint of the observed Artifact definition, including its description and input schema. Exact name alone cannot distinguish a vendor repurpose under the same name. If the vendor renames, removes, or changes the definition, the operation must miss and the whole request must pass through unchanged. This produces under match on drift and prevents deletion of an unrelated future tool.

The breakage boundary is clear. A request that needs publishing or updating a Claude Artifact loses that facility while the default is active. A power user can reenable the same `tool:Artifact` key. Removing the 35,994 character SessionStart hook would erase user supplied automation and context. Removing the 7,034 character system reminder would erase repository instructions. Removing vendor system parts or a broad set of tools has a much larger behavioral surface. Those candidates fail the stated overmatch preference.
