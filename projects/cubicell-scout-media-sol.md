# Cubicell face media, Three.js mechanics scout

## Verdict

Keep WebGL and extend the existing instanced face shader plus atlas owner. Static images and generated pixels fit a fixed RGBA atlas selected by an instance attribute. Video can enter the same fixed shader contract, but each independently playing source requires either an instanced mesh partition or a dynamic atlas copy. TSL and WebGPU are available in Three r185, but they turn this feature into a renderer migration, replace the current shader patch path, add about 102 to 107 KB gzip in a minimal probe, and conflict with the fixed program key invariant on the WebGL compatibility route.

## Path of least resistance

1. Generalize the existing face stencil patch into one face media shader owner. Keep `src/scene/instancedPartMeshCore.ts:createInstancedPartMeshWithGeometry` as the only material construction seam. Compose instance opacity once. Install every sampler and attribute at construction.
2. Keep the current R8 stencil atlas. Add a separate fixed RGBA atlas for static images and generated pixels. Reuse the atlas lifecycle pattern in `src/scene/stencilAtlas.ts:createStencilAtlas` and async invalidation pattern in `src/scene/CubeScene.tsx:StencilAtlasReadyDriver`.
3. Extend the existing face instance write path. Media selection flows through `src/scene/instancedPartMeshCore.ts:syncInstancedPartMesh` and `src/scene/instancedPartMeshCore.ts:patchInstancedPartMesh`; capacity growth already clones and resizes capacity bound geometry attributes.
4. Use one fixed shader graph. A media mode attribute selects solid, stencil, RGBA atlas or video sampler behavior. A 1 by 1 neutral texture remains bound when a channel is unused. The program key is one fixed version string.
5. Treat independently playing video as a bounded partitioning feature. One shared video sampler can cover many instances. Multiple video sources require one instanced face bucket per source unless a measured dynamic atlas is cheaper. Connect active playback to `src/transport/TransportFrameDriver.tsx:TransportFrameDriver` and `src/scene/renderProducers.ts:renderProducers.playback` so demand rendering advances.
6. Mirror the same material and atlas factories in thumbnails. `src/thumbnail/thumbnailArtifact.ts:createThumbnailArtifact` already uses the common instanced face factory and its own atlas. Static CPU bytes can be shared; GPU allocations cannot cross WebGL contexts.
7. Extend `tests/webGlResourceObserver.ts:observeWebGlResources` and the existing stencil browser gate. Assert stable mesh, material and texture identity, zero program creation on media changes and capacity crossings, one draw per populated atlas face batch, bounded texture creation, exact upload ranges and full disposal.

## Static images

An image decoder changes how bytes enter memory, not the face binding model. Decode a project owned Blob through browser image APIs, copy into the RGBA atlas, then discard the temporary decode surface when possible. Sampling an ordinary Three `Texture` per image has the same instancing problem as `VideoTexture`: a sampler uniform is shared across all instances in one draw. All image and video sources used by thumbnail readback, PNG encoding or canvas recording must remain origin clean. Local project Blobs satisfy this without external CORS dependencies.

## Current release drift, r183 through r185

| Release | Relevant change |
|---|---|
| r183 | WebGPU `PostProcessing` was renamed to `RenderPipeline`. Current designs and imports should use `RenderPipeline`. `Clock` was deprecated in favor of `Timer`. Neither affects the recommended WebGL media seam. |
| r184 | `ImageBitmapLoader.load()` and `FileLoader.load()` stopped returning a value. Use their callbacks. This matters only if an image acquisition path chooses those loaders. WebGL pixel storage changes must use `renderer.state.pixelStorei()`. |
| r185 | WebGPURenderer premultiplied alpha behavior changed. Prefer an opaque scene background unless HTML compositing is required. No listed classic material or texture mechanism was deprecated. `SVGLoader.createShapes()` was deprecated, unrelated to raster face media. |

The installed r185 source also contains the new WebGL node compatibility adapter, but it lives under `examples/jsm/tsl` and documents significant limitations. Treat it as migration tooling. The official WebGPU guide still describes WebGPURenderer as experimental and confirms that classic custom shaders and `onBeforeCompile` are unsupported there. See the official [migration guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide).
