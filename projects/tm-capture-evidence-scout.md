# TM capture-path evidence: scout (reuse map + quality map)

Base commit 573a4538, branch feat/capture-request-evidence, read-only survey. All paths relative to `api/src/transport_matters/` unless noted. mitmproxy pinned `>=12.2,<13`, installed 12.2.3 (semantics below verified against installed source of `mitmproxy.http.Message`).

## Reuse Map

Verdict up front: 2 of the 3 capabilities already have a real owner. Header capture and redaction exist and are provider-agnostic in shape and policy; only the call sites are Codex-gated. Original-encoding retention has a partial owner on the response side (the tee) and none on the request side. Divergence marking has no owner.

### 1. Header capture: shape is generic, derivation is generic, only the call site is Codex

- Shape: `storage/base::TransportArtifacts` with `TransportHttpRequestArtifacts` (method, scheme, host, path, headers list of `TransportHeader`) and `TransportHttpResponseArtifacts` (status_code, headers). Nothing in the model is Codex-specific except the free-text `provider` field. `protocol: Literal["websocket","http"]` and `serialize_by_protocol` already drop the WS-only `upgrade`/`close` keys for HTTP records. This artifact can carry Anthropic or Grok headers unchanged.
- Derivation: `codex/transport::build_codex_http_transport_artifacts` reads `flow.request.method/scheme/host/path`, snapshots headers with `codex/transport::_snapshot_headers` (multi=True aware), maps via `codex/transport::_header_models`, then calls `redact_transport_artifacts`. The only Codex-shaped parts are `provider="codex"` and `messages=_http_transport_messages(parse_codex_http_transport_payloads(...))` (SSE event payload parsing for the transport tab). Header/URL capture itself has zero Codex logic.
- Call site: `exchange_recorder/artifacts::derive_codex_http` returns `(None, None, None)` when `ir.provider != "codex"`; that early return is the whole reason Anthropic/Grok get no `transport.json`. Both `exchange_recorder::persist_http_exchange` and `exchange_recorder::_finalize_http_provisional_exchange` call it and pass the result straight into `ExchangeArtifacts.transport`.
- What would have to move: the header/URL portion of `build_codex_http_transport_artifacts` (`_snapshot_headers`, `_header_models`, the request/response artifact construction) is provider-neutral and lives in `codex/transport` only by history. The Codex-specific piece is `messages`. Note also `flow_state::_header_items` is a second copy of the multi=True snapshot logic (see Quality Map).
- Timing caveat (important for fidelity): `build_codex_http_transport_artifacts` snapshots `flow.request.headers` at RESPONSE time. By then `addon_handlers::handle_http_request` may have called `flow.request.set_text(outbound)` (override path) or `pause_session` may have called `set_text` on release; mitmproxy `Message.set_content` re-encodes with the current content-encoding and rewrites `content-length` (verified: `self.headers["content-length"] = str(len(self.raw_content))` unless transfer-encoding present). So today's Codex transport record holds post-mutation request headers, not the client's originals. Original headers are only guaranteed at request time (see 3).
- Frontend mirror: `www/packages/core/src/types/transport.ts::TransportHttpArtifacts` mirrors the Python model field for field. Inspector `ExchangeDetail.tsx` enables the transport tab whenever `detail.transport != null` regardless of provider; the renderer is `inspector/.../detail/CodexTransportPanel.tsx` (name is Codex-shaped, input type is generic `TransportArtifacts`).

### 2. Redaction: provider-agnostic already, and it would redact Anthropic auth correctly

- Owner: `transport_redaction::redact_transport_artifacts` (plus `_redact_headers`, `_redact_header`, `_header_is_sensitive`, `_redact_value`). Operates on `TransportArtifacts` upgrade/request/response header lists only; never touches bodies or `messages`.
- Policy: exact-name set `_SENSITIVE_HEADER_NAMES` = {api-key, apikey, authorization, cookie, proxy-authorization, set-cookie, x-api-key}; suffix rules `-token`, `-session`; prefix set `_SENSITIVE_HEADER_PREFIXES` = {cf-access-, openai-sentinel-, x-auth-, x-csrf-, x-openai-}. `authorization`/`proxy-authorization` keep the scheme (`Bearer [redacted]`), everything else becomes `[redacted]`. Case-insensitive.
- Anthropic: `x-api-key` and `authorization` are both in the exact set, so Anthropic auth headers are covered. Anthropic-specific non-secret headers (`anthropic-version`, `anthropic-beta`) pass through, which is desirable for replay. Grok: `authorization` covered. Not covered by name: nothing Anthropic-shaped is missing that I could find; there is no `openai-organization` style leak concern for Anthropic. Not looked at: session-scoped Anthropic headers beyond `_AUTH_HEADER_KEYS` in `counting`; that set is {x-api-key, authorization, anthropic-version, anthropic-beta}.
- Applied three times by design: at build (`build_codex_*_transport_artifacts`), at write (`storage/disk::DiskStorageBackend._write_exchange_files`), and at read with rewrite for legacy rows (`storage/disk::DiskStorageBackend.read_exchange` → `disk_helpers::_rewrite_transport_json`). `harnesses/certification_run_reader::read_captured_exchange` refuses to certify a transport artifact the read pass would still change. Any new header-bearing artifact must go through the same function or certification will refuse it.
- Tests: `codex/test_transport::test_build_codex_transport_artifacts_redacts_sensitive_upgrade_headers`, `storage/test_disk_exchange::test_read_exchange_redacts_and_rewrites_legacy_transport_headers`; also referenced in `exchange_recorder/test_codex_http_artifacts`, `codex/test_diagnostics`, `harnesses/test_provider_access_recorder`. No dedicated `test_transport_redaction.py` exists (search: `rg -ln "redact_transport_artifacts|_SENSITIVE_HEADER" -g 'test_*.py'`).

### 3. Where method and URL are alive before being dropped

- Object: mitmproxy `flow.request` (`method`, `scheme`, `host`, `port`, `path`, `pretty_url`, `headers`). Alive for the whole flow, but only ORIGINAL at request time.
- Last point on the addon path with client-original headers and body: `addon_handlers::handle_http_request`, after `get_adapter` and before `outbound_request_if_changed` → `flow.request.set_text(...)`. Everything the slice needs (method, URL, headers, `raw_content`, `content-encoding`, `content-length`, `transfer-encoding`) is readable there. Today the only things captured at that point are `counting::set_recent_auth(relevant_auth_headers(flow.request.headers))` (in-process, four Anthropic keys, `counting::_AUTH_HEADER_KEYS`) and, Codex only, `flow_state::snapshot_codex_http_request_headers` (three derivation headers: session-id, thread-id, x-codex-turn-metadata) into `RequestFlowState.codex_request_headers`.
- The natural carrier that already survives to persist time is `flow_state::RequestFlowState` (written by `capture_request_flow_state`, read by `get_request_flow_state`); it carries `raw_request` (decoded, see 4) but no method/URL/headers. `RequestFlowState` is the object that reaches `persist_http_provisional_exchange`, `persist_http_exchange` and `_finalize_http_provisional_exchange`.
- Method/URL are dropped by omission: `IndexEntry` (`storage/base`) has provider/model/path(storage path, not URL) only; `ExchangeArtifacts` has no header slot outside `transport`; `derive_codex_http` short-circuits for non-Codex; `codex/exchange::persist_codex_handshake_failure` and `exchange_recorder::persist_unparsed_exchange` write no transport for HTTP either (the handshake path does write WS `upgrade` host/path via `build_codex_transport_artifacts`).

### 4. Where the ORIGINAL bytes and headers are alive

Request side:
- `request_pipeline::parse_request_ir` does `flow.request.get_text().encode()`: content-decoded and charset-decoded then re-encoded UTF-8. Original bytes are `flow.request.raw_content` (mitmproxy: "raw (potentially compressed) body, never raises"). Original headers `content-encoding` / `content-length` / `transfer-encoding` are on `flow.request.headers` at this moment and untouched by `get_text` (verified: `get_content`/`get_text` are pure reads).
- `exchange_recorder/artifacts::request_raw_bytes` (used only by `persist_unparsed_http_exchange`) prefers `get_text().encode("utf-8", errors="replace")`, falls back to `content` then `raw_content`. Same lossy policy, second copy.
- Exact last-readable point: inside `handle_http_request` before `flow.request.set_text` (override) and before `handle_breakpoint` (release may `set_text`). After either, `content-length` is rewritten and `raw_content` is a re-encode.

Response side:
- `response_stream::install_response_tee` buffers the ENCODED stream chunks (mitmproxy streams bodies undecoded; `live_status_observer::start_http_flow` takes `content_encoding` and installs `_streaming_decompressor`, and `test_live_status_content_encoding` covers gzip/br/zstd, which confirms chunks arrive encoded). `restore_streamed_response` sets `flow.response.raw_content = bytes(buffer)`, so at `addon_handlers::handle_response` the ORIGINAL encoded response bytes are alive as `flow.response.raw_content` and `flow.response.headers` still carries the server's `content-encoding`. `test_response_stream::test_restore_streamed_response_reconstructs_body_and_text` covers this.
- `exchange_recorder/artifacts::extract_response` then persists `flow.response.get_text().encode()` (decoded). `codex/exchange::persist_codex_handshake_failure` is the one place that persists `response.raw_content` verbatim.
- Non-streamed responses: mitmproxy holds `raw_content` as received; same headers available in `handle_response`.
- `addon_handlers::handle_response_headers` is the earliest point with response headers (`content-encoding` is already read there for the live tap).

Existing header snapshot helpers to reuse rather than reinvent: `codex/transport::_snapshot_headers` (multi=True) and `flow_state::_header_items` (multi=True), both private, both duplicates.

### 5. Existing fidelity / divergence concepts

None found for byte-level fidelity of a persisted exchange. What exists (searched `rg "degraded|partial_|unverified|fidelity|diverg|lossy|byte.exact|round.trip|\"transport\.\w+\""` over non-test py):
- `exchange_recorder/unparsed::unparsed_request_ir` stamps `provider_extras["type"] = "transport.parse_failure"` (+ `client_version`); `codex/exchange::_codex_handshake_failure_ir` stamps `provider_extras["type"] = "transport.handshake_failure"`. These are IR-level "this record is exceptional" markers on synthetic requests, not per-exchange evidence-quality flags on real ones. They are the closest existing vocabulary (a `transport.*` type namespace) but they live inside `InternalRequest.provider_extras`, which is the wrong home for evidence about the capture.
- `storage/base::TransportDiagnostic` (severity/code/summary/detail/operator_checks) is a read-time DERIVED view built by `codex/diagnostics::build_codex_transport_diagnostics` from persisted artifacts and returned by `api/v1/exchanges`; it is not persisted and is Codex-gated (`transport.provider != "codex"` → []). It is a presentation of evidence, not evidence.
- `codex/continuity::CodexContinuityQuality = Literal["exact","lossy"]` on `CodexContinuityAllocation` is the only "exact vs lossy" enum in the codebase; it describes turn-index continuity, not bytes. Naming precedent only.
- `harnesses/compatibility::SupportTier = Literal["tested","observed_unverified"]`, `harnesses/access_policy` "allow_unverified": harness/provider-access trust, unrelated to capture.
- `session/wire_normalization` docstring: "tier-1 raw remains the byte-fidelity source"; the wire store records `WireExchangeWrite.request_raw_bytes` (`session/wire_store`) which `wire_store_observer::_submit_exchange` sets to `len(artifacts.request_raw)`, i.e. the DECODED length; column `request_raw_bytes` in `session/dao_statements`.
- `harnesses/certification_run_reader::CapturedExchange.manifest_item` hashes the persisted files (request/request_ir/response/transport sha256): the certification manifest is the only place that asserts "these exact bytes"; it hashes what was stored, not what was on the wire.
Conclusion: no existing marker to extend; the `transport.*` type strings and the exact/lossy naming are the vocabulary to align with.

### 6. Artifact and disk seam

- Smallest landing places, in order of least ripple:
  a. Inside `TransportArtifacts` (`storage/base`), which already has an HTTP request/response shape and a file (`transport.json` via `DiskStorageLayout.artifact_paths().transport`), is already redacted at write and read, already read by `read_exchange`, `certification_run_reader`, `api/v1/exchanges` and the inspector, and already has a TS mirror. Zero new files, zero `IndexEntry` change, zero wire-store change. Cost: `TransportHttpRequestArtifacts`/`TransportHttpResponseArtifacts` gain optional fields, TS mirror `transport.ts` follows, and any Codex `transport.json` sha256 in certification fixtures/manifests changes only if Codex records start carrying the new fields (see `api/tests/fixtures/codex_http_fallback/README.md` and `CapturedExchange.manifest_item`).
  b. A new sibling file in the exchange dir: `DiskStorageLayout.artifact_paths` (add filename + `ExchangeArtifactPaths` field), `DiskStorageBackend._write_exchange_files` and `read_exchange`, `ExchangeArtifacts` field, `storage/test_disk_layout::test_artifact_paths_keep_existing_filenames`. Recovery (`disk_helpers::_recover_index_entry`) reads only `entry.json`/`turn.json`, so a new file does not affect recovery. `read_exchange` treats every non-request file as optional, so old dirs stay readable (no migration; note also `_drop_legacy_flat_anchor_cache` precedent for cache nukes, and memory says this repo has no back-compat obligation).
- `IndexEntry` ripple: none required for either option; `IndexEntry` is not the place for headers (it is the list row broadcast in `emit_exchange` and mirrored to the dashboard). Wire store ripple: none unless the slice wants the divergence flag queryable in Postgres; `WireExchangeWrite` is a frozen model with `request_raw_bytes` that would need a migration in `api/migrations` to gain columns.
- Persist call sites that would need to populate the field: `exchange_recorder::persist_http_provisional_exchange` (request-time; the only place that runs BEFORE mutation on the provisional path), `persist_http_exchange`, `_finalize_http_provisional_exchange`, `_refresh_and_publish_http_outbound_request` (model_copy carries existing artifacts forward, so a request-time transport survives finalize only if finalize does not overwrite `transport` with `derive_codex_http`'s None; today it does overwrite: `"transport": transport` unconditionally).

### 7. Consumers of the new field

- `baseline_capture::_build_probe_evidence`: reads `captured.request_raw`, `captured.request_ir`, `captured.entry.id` only; ignores transport. Would ignore a new field. Note `baseline_capture::_wait_for_correlated_exchange` requires `request_raw` + `response_ir` files to exist; unaffected.
- `drift_capture::detect_unknown_shapes`: iterates `artifacts.transport.messages` (event_type, payload_text) only; ignores headers. Would ignore.

Tolerates unknown extra keys? ## Quality Map

1. Duplicate header snapshot logic: `codex/transport::_snapshot_headers` and `flow_state::_header_items` both implement `items(multi=True)` with `TypeError` fallback. Refactor-during: the slice must snapshot headers for all providers, so pick one owner (a neutral module, not `codex/`) and point both callers at it. Reason: adding a third copy is the exact anti-pattern the slice will be reviewed for.
2. Duplicate lossy body policy: `request_pipeline::parse_request_ir` (`get_text().encode()`), `exchange_recorder/artifacts::request_raw_bytes` (`get_text().encode(errors="replace")` + fallbacks), `exchange_recorder/artifacts::extract_response` (`get_text().encode()`). Three places decide "what bytes are the raw"; the slice changes that decision. Refactor-during: one owner for "raw request bytes" and one for "raw response bytes" so the divergence check has a single seam to hook.
3. Header timing bug in existing Codex HTTP transport: `build_codex_http_transport_artifacts` snapshots request headers at response time, after `set_text` may have rewritten `content-length` (and re-encoded body). Refactor-first or at least fix-in-slice: any "original headers" claim is false for overridden Codex requests today; the slice's request-time capture makes this obsolete if the Codex builder is fed the request-time snapshot instead of `flow.request.headers`.
4. `derive_codex_http` conflates three outputs (transport, derived turn, list summary) and is the sole gate that hides transport from non-Codex providers. Refactor-during: split "transport for any provider" from "Codex derivation" so `persist_http_exchange`/`_finalize_http_provisional_exchange` do not need a provider branch. Reason: the current shape forces the new code into a Codex-named function.
5. `_finalize_http_provisional_exchange` overwrites `"transport": transport` unconditionally on `existing_artifacts.model_copy`. If request-time evidence lands in `transport` at provisional time, finalize must merge, not replace. Refactor-during (it is inside the change surface anyway).
6. Codex-shaped naming over generic types: `codex/transport` hosts generic HTTP transport building; inspector `CodexTransportPanel.tsx` renders generic `TransportArtifacts`; `wire_store_observer._request_kind` and `codex/diagnostics` gate on `provider == "codex"` correctly. Defer the rename of the panel (cosmetic, frontend, out of slice); move the generic builder now (see 1 and 4).
7. Redaction applied at build, write and read. Not duplication of logic (one function), but three call sites; the read-time rewrite exists for legacy rows and certification depends on it. Defer: leave as is, it is the safety net the slice must go through, not around.
8. `counting::set_recent_auth` is called for every provider with `relevant_auth_headers` filtered to Anthropic keys (`_AUTH_HEADER_KEYS` includes `anthropic-version`, `anthropic-beta`). Not in scope for evidence; note only that it must never be the source for persisted headers (it is a token-count credential cache). Defer.
9. `wire_store_observer._submit_exchange` sets `request_raw_bytes=len(artifacts.request_raw)` (decoded length) with a column name that implies wire bytes. Defer unless the slice defines "raw" as wire bytes, in which case this becomes correct for free; otherwise rename later. Reason: wire-store schema change needs a migration and is outside capture-path.
10. Dead-ish: `codex/transport::_message_event_type` has no callers found (`rg "_message_event_type"` returns only its definition). Defer, trivial, not on the path.
11. Sizes: no production file on the path exceeds 700 (largest touched: `codex/transport` 571, `addon_handlers` 546, `storage/disk` 595, `exchange_recorder/__init__` 527). Adding a generic transport builder to `codex/transport` would be the wrong home regardless of size; a neutral module (or `exchange_recorder/artifacts`, 233 lines, which already owns request/response artifact assembly) has room.
12. Ambient interpreter trap: `python3` on this Mac is 3.13 and SyntaxErrors on PEP 758 `except A, B:` used throughout; the repo is `>=3.14` via `uv run` (uv created `api/.venv`, gitignored, during this scout; tree stays pristine per `git status --short`).

## Plan (reuse map only, no design)

Bind to: `storage/base::TransportArtifacts` + `TransportHttpRequestArtifacts`/`TransportHttpResponseArtifacts` as the artifact; `transport_redaction::redact_transport_artifacts` as the redaction; `codex/transport::build_codex_http_transport_artifacts` header/URL portion (relocated) as the derivation; `flow_state::RequestFlowState` as the carrier from request hook to persist; `addon_handlers::handle_http_request` (pre-`set_text`) as the request-time capture point; `addon_handlers::handle_response` after `response_stream::restore_streamed_response` as the response-time capture point where `flow.response.raw_content` and headers are original; `exchange_recorder::persist_http_provisional_exchange`/`persist_http_exchange`/`_finalize_http_provisional_exchange` as the persist points; `storage/disk::DiskStorageBackend._write_exchange_files`/`read_exchange` as the disk seam (no new file needed if the field lives in `transport.json`); TS mirror `www/packages/core/src/types/transport.ts`.

Not found (with searches run): a per-exchange evidence-fidelity flag (`rg "degraded|partial_|unverified|fidelity|diverg|lossy|byte.exact|round.trip"`), a request-header persistence path for non-Codex (`rg "request_raw_bytes|content-encoding|content_encoding|content-length|content_length|raw_content|get_content\("`), a `TransportArtifacts` builder outside `codex/transport` (`rg -ln TransportArtifacts` non-test), a dedicated redaction test module (`rg -ln "redact_transport_artifacts|_SENSITIVE_HEADER" -g 'test_*.py'`).

Gates: `cd api && just check && just test`; `pnpm --filter @tm/core typecheck` if `transport.ts` changes; `just test-affected origin/main` for the local loop.
