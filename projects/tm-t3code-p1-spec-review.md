# P1 Spec Adversarial Review

## Blocker

- [Blocker] Spec sections §2b, §8 slice 1, §10 Q1. The serving host plan treats `/v1/runs*` as if it only belongs to the live run terminal surface. In the current app that prefix also owns Python artifact and metadata routes: `api/src/transport_matters/main.py::create_app` mounts `run_routes.router`, `exchanges.run_router`, and `meta.run_router` under `/v1`; `api/src/transport_matters/api/v1/exchanges.py::RUN_EXCHANGES_ROUTE_PREFIX` is `/runs/{run_id}/exchanges`; `api/src/transport_matters/api/v1/meta.py::get_run_meta` is mounted at `/v1/runs/{run_id}/meta`. The frontend reaches those routes through the same relative transport: `www/packages/core/src/transport.ts::fetchExchange`, `fetchTurnContent`, `fetchPipelineTokens`, and `fetchMeta`. So Q1's recommended "Python app reverse proxies `/v1/runs*` to the TS host" would steal exchange and meta routes from Python, while "TS host serves the canvas bundle" would strand `/api/meta`, `/v1/spaces`, `/v1/sessions`, and `/v1/runtime-templates` unless the host also proxies the wider Python API. Slice 1 must prove the full canvas origin contract, not only stub `/v1/runs`. The spec needs an explicit route ownership table before implementation.

## Major

- [Major] Spec sections §3, §4, §8 slice 5. The cross platform parent death plan names the right primitives, but does not define an implementable seam for them. Current code confirms the debt: `desktop/src/backendProcess.ts::launchBackendProcess` uses ordinary Node `child_process.spawn`; `api/src/transport_matters/desktop_runtime.py::stop_desktop_record` uses `os.kill`; `api/src/transport_matters/pty_session.py::spawn_pty_process` uses POSIX PTY, `setsid`, `TIOCSCTTY`, and `killpg` semantics. Windows Job Objects need a handle owned by the TS host or Electron and an API to assign the Python sidecar and descendants. Linux `PR_SET_PDEATHSIG` must be installed in the child path and guarded against the parent dying before installation. macOS can use the Python watchdog. Without naming the Node native bridge, helper executable, or bootstrap contract, the host SIGKILL row in §4 is still an assertion.

- [Major] Spec section §6. I would not adopt Effect for P1 on the evidence in this tree. The dependency check found no `effect` or `@effect` entries, and `packages/activity/package.json` depends on `xstate`. The existing desktop launcher surface is small plain TS, with the relevant seams in `desktop/src/backendProcess.ts::launchBackendProcess` and `desktop/src/main.ts::registerAppLifecycle`. Effect helps express scope finalizers, but the hard P1 risks are route ownership, native parent death reaping, capture RPC semantics, and terminal parity. Those are not solved by Effect. Plain TS with an explicit shutdown coordinator is the lower risk default unless Stuart explicitly accepts a net new runtime for future strategic alignment, not just this slice.

- [Major] Spec section §8 slice 4. Slice 4 is several slices hidden under one heading. It ports PTY spawn, the terminal socket, scrollback, fanout, run state, capture integration, and then deletes the Python run surface. Current behavior spans `api/src/transport_matters/run_manager.py::RunManager._prepare_request`, `_start_run_terminal`, and `_teardown_run`; `api/src/transport_matters/run_terminal.py::ScrollbackRing` and `TerminalFanout`; `api/src/transport_matters/api/v1/run_routes.py::run_terminal_socket` and `bridge_attached_run_terminal`; `www/packages/canvas/src/session-canvas/viewers/terminal/CapturedRunPane.tsx::CapturedRunPane`; and `www/packages/canvas/src/session-canvas/model/capturedRunStore.ts::ensureRun` plus `stopRun`. That needs smaller cuts: PTY adapter and wire contract, fanout parity, create plus attach over fake capture, capture RPC integration, then route cutover. Otherwise the first real behavioral PR carries too much risk to review well.

## Minor

- [Minor] Spec sections §4 and §8 use `DELETE /v1/runs/{id}` for explicit terminate, but the current public route and frontend contract are `POST /v1/runs/{run_id}/terminate`: `api/src/transport_matters/api/v1/run_routes.py::terminate_run`, `www/packages/core/src/transport.ts::terminateRun`, and `www/packages/canvas/src/session-canvas/model/capturedRunStore.ts::stopRun`. Changing this is allowed pre release, but the spec should call it out as a contract change or preserve the existing route during the TS host cutover.

## Verified Load Bearing Claims

- `api/src/transport_matters/captured_run.py::prepare_captured_run` returns `CapturedRunSpawnSpec` plus `CapturedRunLease`; `api/src/transport_matters/captured_run_models.py::CapturedRunSpawnSpec` contains the serializable launch envelope, and `CapturedRunLease.close` idempotently terminates the supervisor, releases the workspace lock, removes the manifest, and closes the resource stack.
- `www/packages/canvas/src/session-canvas/viewers/terminal/terminalSocket.ts::runTerminalSocketUrl`, `www/packages/core/src/transport.ts::createCapturedRun`, `listRuns`, and `getRun` use same origin relative routes for the live run API.
- `api/src/transport_matters/run_terminal.py::ScrollbackRing` and `TerminalFanout` provide sequence based scrollback, multi attachment queues, and resume by snapshot plus `start_seq`. `api/src/transport_matters/pty_session.py::spawn_pty_process` is POSIX PTY code.
- Effect is absent from package manifests and `packages/activity/package.json` uses `xstate`.
