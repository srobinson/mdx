## P-vs-F verdict per finding
- Selection focus toggle: F. It has two truths and a hook-level seed workaround to survive view-lane coalescing.
- Wheel zoom: F. It mutates the camera authority and rendered camera through a private path instead of the command lane.
- Unresolved reset view command: F. It is a view action routed through synchronous hook logic because target resolution has no proper command-side home.
- Editor session toggles and cycles: F. They are state transitions whose owner is a React closure, not an aggregate action over current state.
- Command repeatability metadata: F. It still depends on object identity and adapter-specific behavior rather than command data.
- Camera driver runtime module: F. It concentrates too many separate responsibilities in one near-limit file.

## Notes
- Projection toggle checked as the P reference path: `scene.camera.projection` is the domain truth, `CameraDriver` observes it, `beginMorph` and `advanceMorph` own the transition axis, and the projection change does not enter the coalesced view lane.
- Selection snapshot checked as fine by itself: `src/interaction/snapshot.ts` composes selection from the store through a port, matching `INTERACTIVE.md`; the smell is only the separate selection-focus active flag mirrored against camera focus state.
- Transport checked and not ranked: `src/anim/TransportDriver.tsx` has one clock driver over `editor.transport`, and there is not yet a competing camera possession state in this tree.
- Direct panel scene and selection operations checked and not ranked: `INTERACTIVE.md` explicitly names legacy direct clients as later adapter work, and these paths do not mirror camera authority state today.
- Orbit repeat checked and not ranked separately: keyboard and keypad repeat orbit as discrete taps, which matches the current lesson that orbit should remain detent based rather than continuous glide.
