# Transport Matters lab spawn scout

Root cause: static lab worktree sentinel. The lab does send a `worktreeId`, but it is the literal string `lab`, which now fails the `/v1/runs` UUID contract before worktree lookup.

## Reuse Map

- User path: `www/src/session-canvas/lab/CanvasLabRoute.tsx+CanvasLabRoute` reads `addCapturedRun` from the lab store. The Spawn Claude and Spawn Codex buttons call `addCapturedRun("claude")` and `addCapturedRun("codex")`.
- Missing session seeding: `www/src/session-canvas/lab/CanvasLabRoute.tsx+CanvasLabRoute` does not import `www/src/hooks/useMeta.ts+useMeta`, does not parse launch query through `www/src/session-canvas/route.ts+parseCanvasLaunchContext`, and does not call an `adoptDefaultWorktree` equivalent. `www/src/session-canvas/lab/CanvasLabRoute.tsx+labContentProps` also synthesizes viewer launch context with `worktreeId: null`.
- Lab store bug site: `www/src/session-canvas/lab/canvasLabStore.ts+useCanvasLabStore.addCapturedRun` calls `www/src/session-canvas/model/spawn.ts+createCapturedRunRef(provider, LAB_WORKTREE_ID, label)`. `LAB_WORKTREE_ID` is the literal `lab`. `addTerminal` uses the same sentinel for terminal refs.
- Shared frontend launch path: `www/src/session-canvas/model/spawn.ts+createCapturedRunRef` persists the ref's `worktreeId`; `www/src/session-canvas/viewers/terminal/CapturedRunPane.tsx+CapturedRunPane` passes that value to `www/src/session-canvas/model/capturedRunStore.ts+useCapturedRunStore.ensureRun`; `ensureRun` calls `www/src/api.ts+createCapturedRun`; `createCapturedRun` serializes the defined `worktreeId` into `POST /v1/runs`.
- Backend contract: `api/src/transport_matters/api/v1/run_routes.py+create_run` calls `_resolved_worktree`; `_resolved_worktree` calls `_parse_uuid_id` with `invalid_worktree_id` and `worktree_required`, then resolves through `api/src/transport_matters/space/store.py+SpaceStore.resolve_worktree`. The literal `lab` fails at UUID parsing, so the manager never spawns a run.
- Existing PR #182 reuse seam: `www/src/session-canvas/SessionCanvasRoute.tsx+SessionCanvasRoute` seeds the main canvas default from `GET /api/meta` by calling `www/src/session-canvas/model/canvasStore.ts+useCanvasStore.adoptDefaultWorktree` when the launch URL has no explicit `worktree_id`. `www/src/session-canvas/model/canvasStore.ts+useCanvasStore.addCapturedRun` then uses the per spawn `worktreeId` or `defaultWorktreeId`, and throws before spawning when no rooted worktree exists.
- Route purpose: `/canvas-lab` is active, not dead. `www/src/rootShell.tsx+RootShell` mounts it, `www/src/session-canvas/components/RouteSwitcher.tsx+CANVAS_ROUTES` exposes it as Lab, `desktop/src/window.ts+isAllowedHostedPath` allows it as a hosted path, and the launcher model includes a go to lab command. It is an experimental surface, but it is reachable through first class navigation.
- Duplication map: `www/src/session-canvas/model/canvasStore.ts+useCanvasStore` and `www/src/session-canvas/lab/canvasLabStore.ts+useCanvasLabStore` both own spawn, dock, minimize, close, restore, and captured run pane creation over shared `paneAffordances` and `createCapturedRunRef`. The lab's separate layout and persistence are intentional, but its launch target is a stale parallel default rather than the #182 worktree default seam.

## Quality Map

- Actual failure evidence from the running backend at `127.0.0.1:8788`: `GET /api/meta` returned HTTP 200 with `space_id=f4fd000b-82f7-44b7-b407-c210ca61c501` and `worktree_id=023ca3fb-51e6-4cf1-9928-fcacfa848c29`. `GET /v1/spaces/f4fd000b-82f7-44b7-b407-c210ca61c501/worktrees` returned UUID worktree IDs, none named `lab`.
- Exact lab payload evidence: `POST /v1/runs` with `{"harness":"claude","worktreeId":"lab","oscColorReplies":true,"bypassPermissions":false}` and `Origin: http://127.0.0.1:8788` returned HTTP 400 with `code=invalid_worktree_id` and message `worktreeId must be a UUID`.
- Control evidence: the same POST without `worktreeId` returned HTTP 400 with `code=worktree_required`. The lab failure mode is therefore not an omitted field. It is an invalid sentinel field.
- UI surface detail: `www/src/api.ts+throwWithDetail` only lifts string `detail` values, while this backend response returns an object detail. `www/src/session-canvas/viewers/terminal/CapturedRunPane.tsx+spawnErrorMessage` will likely show the generic `Failed to spawn captured run: 400` string even though the backend code is `invalid_worktree_id`.
- Existing tests cover the wrong boundary. `www/src/session-canvas/lab/CanvasLabRoute.test.tsx` covers spawn button visibility and rehydration. `www/src/session-canvas/lab/canvasLabStore.capturedRuns.test.ts` proves independent pane and key creation, but it does not assert a real worktree ID. `www/src/session-canvas/model/canvasStore.test.ts+describe adoptDefaultWorktree (meta seeding)` covers the #182 main canvas fix and is the behavior to reuse.
- Missing coverage: lab route meta adoption, explicit query worktree precedence if `/canvas-lab` carries `worktree_id`, and lab `addCapturedRun` refusing to spawn when no rooted worktree is available.
- Required gates after a fix: run repo root `just check` and `just test`. Do not use `just ci` for this task.

## Plan

1. Fix by reuse. Keep `/canvas-lab`; do not delete it for this bug. Do not unify the stores in this slice, because the lab still has distinct layout, persistence, and experiment controls. The immediate defect is its stale worktree default.
2. Add a lab default worktree contract that mirrors `www/src/session-canvas/model/canvasStore.ts+useCanvasStore.adoptDefaultWorktree`: store `spaceId` and `defaultWorktreeId` in `www/src/session-canvas/lab/canvasLabStore.ts+useCanvasLabStore`, make adoption idempotent, and make an explicit URL worktree own the default. Extract a small shared helper only if it removes duplication without creating a vague abstraction.
3. In `www/src/session-canvas/lab/CanvasLabRoute.tsx+CanvasLabRoute`, reuse `www/src/hooks/useMeta.ts+useMeta` and `www/src/session-canvas/route.ts+parseCanvasLaunchContext`. Seed the lab store from `launch.worktreeId` when present. Otherwise seed from `meta.worktreeId` through the lab `adoptDefaultWorktree`, matching `www/src/session-canvas/SessionCanvasRoute.tsx+SessionCanvasRoute`.
4. Change `www/src/session-canvas/lab/canvasLabStore.ts+useCanvasLabStore.addCapturedRun` to use the resolved lab default worktree instead of `LAB_WORKTREE_ID`. Throw or disable before pane creation when the default is null, matching the main canvas guard. Apply the same root to `addTerminal` so the lab has one worktree contract.
5. Delete or repoint `LAB_WORKTREE_ID`. Keeping `lab` as a fallback would preserve the 400 `invalid_worktree_id` path.
6. Add regression tests in `www/src/session-canvas/lab/canvasLabStore.capturedRuns.test.ts` and `www/src/session-canvas/lab/CanvasLabRoute.test.tsx`: meta seeded spawn carries the backend UUID, explicit `worktree_id` query wins over meta, and missing default blocks spawn before `createCapturedRun` can POST.
7. Run repo root `just check` and `just test` before implementation signoff.
