## Findings

**[BLOCKER] #3 `packages/activity/src/domain/runActivityContext.ts` `foldReasoning`/`foldGenerating` + `packages/activity/src/domain/runActivityMachine.ts` `reasoning`/`generating` state nodes — §5.3/§5.4 rest on two false reuse claims; as specified, the non-pollution property and the block-stop→retraction path do not exist.**
The spec asserts (§5.4) "the wire stream routes them through `foldWireAsserted` ... the PR-3 non-pollution property reused verbatim" and "the machine's states change not at all", and (§5.3) that block stop retracts "under the per-state `wireRetractionRestores` guards and `WIRE_RETRACTED_TRANSITIONS`. No new event type, no new fold." Verified against source, three breaks: (a) only `foldToolUse`, `foldTurnIdle`, `foldQuestionAsked`, `foldTranscriptError` carry the `eventStream(event) === "wire"` branch — `foldReasoning` and `foldGenerating` call `markApplied` directly and would write `lastActiveStatus` for a wire-stream event, polluting the record-owned baseline that `statusAfterWireRetraction` recomputes from (the retraction would "restore" the wire's own state); (b) those folds never stamp `event.wireExchangeId`, and `markApplied`'s ownership branch only preserves, never sets, `wireAssertedExchangeId` for wire-stream events — so a live reasoning/generating assert leaves `wireAssertedExchangeId` unset and the service's trailing retraction branch (`if (context.wireAssertedExchangeId !== null)`) never arms; (c) `wire.retracted` transitions exist on exactly `running-tools`, `needs-you-asked`, `idle`, `stalled` — the `reasoning` and `generating` state nodes have none, so even a correctly-armed retraction event is silently dropped from the two states live asserts newly own (XState ignores events with no transition). Why it matters: an implementer following the spec ships §5.3's headline mechanism dead — after a block stop or turn terminal, status sticks on Thinking/Responding until a record or the next finalize moves it, and the baseline is polluted meanwhile. The fix is small (wire branches in the two folds, `WIRE_RETRACTED_TRANSITIONS` on the two state nodes, update the `WireRetractedEvent` doc comment "exactly the wire-assertable states") but the spec must be amended to own these machine/fold changes explicitly; slice 4's stop→retraction red test would fail against the unchanged machine, contradicting the spec text.

**[BLOCKER] #1+#3 spec §5.2/§5.3 + `packages/activity/src/service/activityIngestion.ts` `reconcileWireSnapshot` + `api/src/transport_matters/exchange_recorder.py` `persist_http_provisional_exchange` — the live admission contract is unsound under a lost terminal fact: a stale live row overrides fresher record truth on every reconcile pass, indefinitely.**
Three verified facts compound: (i) `reconcileWireSnapshot` re-derives and re-sends the admitted candidate on **every** pass — `isNewEvent` returns true unconditionally for the wire stream, and today's no-flap safety is the *causal* admission contract (`wireCandidateAdmitted`: resolved tool ids, cold-start), not any same-assert comparison; the spec's claimed property that a re-read row "neither re-asserts nor retracts" names no mechanism, and `live-reasoning`/`live-generating` admit **unconditionally** with no causal anchor to self-refuse. (ii) The machine accepts `record.generating`/`record.reasoning` from every non-terminal state including `needs-you-asked` and `idle` (verified transition tables), so each re-assert overrides record-owned truth. (iii) The freshness backstop `live.ts > snapshot.ts` is anchored wrong: for Claude's primary streamed path `entry.ts` is stamped at **provisional creation (request start)** and kept by `_finalize_http_provisional_exchange`, flowing into `wire_exchange.ts` via `WireExchangeWrite(ts=entry.ts)` — so every live fact of turn N postdates turn N's own snapshot ts and "dated at or before the latest finalized exchange" never triggers; the finalize plane cannot spend the overlay on ts as cited. Concrete failure: user hits Esc mid-response (or the best-effort terminal upsert fails, or the emitter dies) leaving `kind='generating'`; the transcript journals the interrupt and the machine reaches `needs-you-asked`/`idle`; every subsequent NOTIFY-triggered pass re-admits the stale live candidate and flips status back to Responding; each re-assert (`reenter: true`) also restarts the stall timer it would otherwise escape by. The user is shown Responding while the agent waits on them — the attention deadlock this redesign exists to kill, now sticky instead of laggy. Required: anchor the spent-overlay comparison to a finalize-commit-time column (`wire_exchange.created_at`, already what `WIRE_SNAPSHOT_BY_RUN_SQL` orders by) and specify an explicit staleness mechanism (same-assert no-resend once asserted, plus a freshness bound or abort-path terminal — see the Major), each with a named red test in slice 4.

**[MAJOR] #1 spec §2/§4.3 — no terminal fact on aborted or errored flows.**
The vocabulary maps only in-stream events (`message_delta` stop_reason / `message_stop`; `response.completed`/`failed`). A killed or errored flow (user Esc, network drop, upstream 5xx mid-stream) delivers no terminal event, `handle_response` may never run, no finalize row lands, and the live row freezes on its last non-null kind. Even with both blockers fixed, status shows Thinking/Responding for up to `DEFAULT_STALL_TIMEOUT_MS` (10 min) after the wire went silent. The design needs a best-effort `kind = null` emit on flow completion/error (mitmproxy error hook or tap teardown in the per-flow tap `handle_response_headers` installs), and slice 3's red-test list should include it.

**[MINOR] #2/#3 spec §2/§5.3 — inter-block stop→start retraction flicker.**
`content_block_stop` and the next `content_block_start` arriving in separate chunks produce two writes + two reconcile passes: retract (restore record baseline — early in a turn that is the *previous* turn's `idle`/`needs-you-asked`) then re-assert ms later. The latest-wins slot only coalesces within an in-flight write window. Cheap fix worth specifying: within one `feed()` batch, emit only the final tracked state; and/or defer a stop-fact write one slot cycle so an immediately following start supersedes it.

**[MINOR] #5 spec §2.1 — `redacted_thinking` unmapped.**
`content_block_start` with `content_block.type == "redacted_thinking"` classifies as nothing, and redacted blocks stream none of the three mapped delta types, so the heal rule never fires: a turn opening with redacted thinking shows no live state until the next visible block. Map `redacted_thinking` → `reasoning`.

**[MINOR] #5 spec §4.1 — the reframer must retain a byte tail, and the proof suite must force multi-byte splits.**
`iter_sse_data_objects` decodes with `errors="replace"`; an incremental sibling that decodes per chunk and retains a string tail corrupts JSON when a chunk boundary splits a multi-byte UTF-8 sequence. Pin: the unterminated tail is kept as bytes (or an incremental decoder is used), and the every-byte-boundary proof test's canned body contains non-ASCII payload content so this fails red.

**[MINOR] #5 spec §2.2/§4.3 — Codex WS tap direction unstated.**
`handle_codex_websocket_message` processes both directions (`message.from_client` observed in source); the classifier tap should be pinned to server frames only. Low risk (client frames carry none of the mapped event types) but it is one sentence and one test assertion.

## v4 final-confirm addendum (2026-07-10, spec v4 re-read cold)

All five confirm questions verified at source:

1. **Closed-generation straggler is a genuine no-op.** The §3.1 upsert guard `WHERE NOT (run_live_status.closed AND run_live_status.generation = excluded.generation)` rejects a post-close write of the same generation at statement level; under READ COMMITTED, `ON CONFLICT DO UPDATE` waits on the row lock and re-evaluates the predicate against the latest committed row version, so both interleavings (straggler-then-close, close-then-straggler) converge to `closed = true, kind = NULL`. No resurrection.
2. **A new generation reopens the row.** The `DO UPDATE SET` list explicitly includes `closed = false`; the guard passes for a differing generation (`NOT (true AND false)`), so turn N+1's first assert reopens correctly.
3. **A slow finalize cannot null the next turn's row.** The close is `WHERE run_id = $1 AND generation = $2` with `$2 = write.exchange_id`; a row already holding generation H is untouched by G's late close (zero-row UPDATE, no-op). The remaining cross-turn hazard (a turn-G live straggler landing after turn-H opened, which the guard alone would admit since the row is open) is excluded by the per-run single-in-flight latest-wins slot: within the one emitter process per run, a G write can never commit after an H write is issued, and the abort emit rides the same slot.
4. **Generation availability and both residuals verified.** `RequestFlowState.provisional_exchange_id` and `track_assignment` (`flow_state.py`) are both set in `handle_http_request` (`run_pipeline` → `update_request_flow_state` → `persist_http_provisional_exchange`) in the request hook, before response headers — the fence token and the producer-side subagent skip are real at tap-install time; `TransportMattersAddon.error` exists and already routes to `delete_http_provisional_exchange`, so the §4.3 abort terminal has its hook; `pgWireIntegration.test.ts` T12 pins the finalize-plane subagent precedent; the §5.4 owned machine changes and §5.5 reds close blocker 1; the admit-once entry anchor + same-assert-standing step close blocker 2's re-admit loop (the anchor lives on `RunIngestionEntry`, correctly surviving record-stream clearing of `wireAssertedExchangeId`). Slice DAG 1→2→3→4→5 is coherent; slice 2's machine changes are genuinely dark (nothing mints wire-stream reasoning/generating before slice 4).
5. **One new internal contradiction (doc-level, no mechanical risk):** §5.1 states the live-status DTO "carries only `run_id`, `seq`, `kind`, `tool_call_id`", but the §5.2 live candidate shapes carry `ts: string` and `wireCandidateEvent` needs an event ts for the machine's replay-deterministic `sinceTs`/`lastEventTs` stamping — the row's `ts` must be surfaced on the DTO (stamping only, never adjudication, per §3.1's own rule). One-sentence spec fix; the §5.2 type shapes already force the correct implementation.

v4 verdict: fence sound, both blockers closed; conditional only on the §5.1/§5.2 ts contradiction.

## Verdict (v1 review)

Conditional. The architecture (ephemeral overlay + doorbell + reuse of the retraction plane) is right and the plane-crossing, invariant, frozen-plane, and empty-at-spawn sections survive adversarial reading against source. The two blockers share a root cause: §5 was written against the scout's summary of the wire plane ("the `stream: "wire"` tagging plus `foldWireAsserted` show exactly how a wire-origin event rides the existing types") without checking that the two *specific* folds and two *specific* state nodes the live kinds need are among the ones wired — they are exactly the ones that are not, because today's wire plane never mints reasoning/generating. Both fixes are small and well-shaped; the admission/staleness contract needs one real design decision (freshness anchor + same-assert semantics), not a rewrite.
