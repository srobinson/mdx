- **Workspace scoping**: `launch_policy.scoped_launch_workdir` recovers the workspace root by walking the actor session cwd's parents until `workspace_key(candidate) == principal.workspace_id` (canonical identity, not string prefix), resolves the requested path (symlinks followed), and rejects escape with `forbidden`. The symlink-escape test (`workspace/escape -> outside`) and the child-director root-recovery test both pass through the real resolver. Filesystem work runs in `asyncio.to_thread`. stop/interrupt gate targets by workspace-activity membership, mirroring prompt's visibility gate.
- **Grant-at-launch**: reuses the S1 minting path untouched — `controlPlaneGrant` on the `POST /v1/runs` body → capture lease `_persist_control_plane_grant`. `provisioning.prepare_control_plane_grant` now takes `workspace_root` so a subdirectory launch's grant carries the root workspace identity (keeps the child visible/promptable in the director's workspace). Verified in the integration test over the real HTTP hop.
- **Idempotency**: service passes `dispatch_id` as the gateway `idempotencyKey`; the gateway's `createWithDisposition` single-flights, returns an authoritative `created` flag, and 409s changed-intent reuse via a fingerprint. first_prompt and audit key off `created` plus a service-side replay record. Once-only spawn AND once-only prompt proven in unit (`test_launch_reuses_caller_dispatch_id_for_retries`: 1 input call, 1 audit row, retry receipt `skipped`) and integration (retry crosses the real HTTP hop, `spawn_count == 1`). Cross-owner replay isolation and changed-intent rejection tested.

## 2. first_prompt: issue (one confirmed defect on an otherwise correct design)

Readiness gates on the gateway run state reaching `RUNNING` via the new typed `get_run`, not Activity `starting` — matching the acceptance criterion (gateway-authoritative, not the projection-lagged plane). Receipt vocabulary is `delivered | failed | skipped` (absent when no prompt). Delivery rides `deliver_input(mode="nudge")` with the standard envelope.

**F1 (CONFIRMED, correctness): `_wait_for_running` never evaluates its final poll** (`launch_delivery.py:66-78`). The loop checks `state == "RUNNING"` at the top of each iteration and fetches `get_run` at the bottom, so the Nth fetch's result is assigned and then discarded when the loop exits. With N attempts there are N fetches but only N−1 ever gate delivery. Failure scenario: `launch_ready_attempts=1` (exactly the config both the unit and integration fixtures use) with a `STARTING` create response → the single fetch is executed and ignored, `deliver_first_prompt` returns `"failed"` even when the run is already RUNNING; at the default 31 attempts one attempt of the ~3s budget is silently wasted and a run that becomes RUNNING on the last poll loses its first prompt. Compounding test gap: no test anywhere drives the STARTING→RUNNING transition through the poll loop (fixtures use immediate-RUNNING or never-RUNNING), so the loop's core purpose is unexercised. The sibling poll loop in `desktop_runtime.py` gets the check-after-fetch boundary right, underlining that this is a per-copy hand-rolled loop bug.

Findings (ranked after F1):

**F2 (CONFIRMED, resource lifecycle + altitude): `_launch_replays` never evicts and duplicates gateway idempotency** (`service.py:128, 424-434`). Every launch — including the default no-caller-dispatch_id case where the service mints a fresh UUID — permanently inserts a `_LaunchReplay` holding the intent, the `LaunchResult`, and a full `ControlPlaneAction`. A long-lived API leaks one per launch forever; the gateway's `pendingCreates` at least self-cleans on failure and already owns single-flight + changed-intent conflict (with a different comparison basis than `_LaunchIntent`, so the two rules can disagree). The map's only unique value is audit-once-across-retries; that needs an evict-after-audited or bounded/TTL structure, not an immortal dict. Same defect class as S5's unevicted `byRun` map.

**F3 (CONFIRMED, efficiency): launch retry and hot path waste** (`service.py:251-268, 270-299`). (a) Two identical `sessions_for_runs(principal, (principal.run_id,))` reads per launch — `_resolve_launch_workdir` fetches the row for `cwd`, then `_launch_envelope → _resolve_actor_name` refetches it for `title`; one row serves both. (b) An idempotent retry redoes both reads, the `to_thread` path resolution, and envelope formatting before ever consulting the replay cache. (c) The ≤3.1s readiness poll runs while holding the per-dispatch replay lock, so a concurrent same-key retry blocks for the whole poll.

**F4 (CONFIRMED, receipt honesty): `stop` cannot report `unknown`** (`run_proxy.py::_typed_run_request` + `service.py:324-348`). `_typed_run_request` folds every `httpx.RequestError` — including post-send losses — into `GatewayUnavailableError`, so `stop` reports `failed/busy_gateway` for an ambiguous terminate that may have landed. `ManageStatus` has `unknown` and `interrupt` uses it (via `deliver_input`'s post-send classification); `stop` conflates provably-not-sent with sent-but-lost, against the S5-adjudicated vocabulary. Mitigated by terminate being retry-safe (a second stop of a settled run returns `stopped`), which is why this is a minor, not a blocker.

**F5 (CONFIRMED, dead code): `validRuntimeNudge` has zero callers** (`RunInputDelivery.ts:44` + `index.ts` barrel). The nudge-fold deleted both consumers; the orphaned export invites a future caller to pick the wrong validator (it forbids `\n`; `validRuntimeInput` allows it). The single-line watch invariant now lives only in `format_watch_envelope`'s terminal-safe text — acceptable, but the dead export should go.

**F6 (CONFIRMED, DRY): three same-commit duplications.** (a) `_launch_envelope` (`service.py:454-472`) is byte-for-byte the envelope block still inlined in `prompt` (`service.py:178-187`) — prompt should call the helper. (b) The workspace-containment predicate `X != root and not X.is_relative_to(root)` appears in both `launch_policy.py:45` and `captured_run_context.py:304` with only the raised exception differing. (c) `stop`/`interrupt` share the whole prologue/epilogue (gate → deps → dispatch → visibility pre-check → result → audit) with drifted internal shape (reason-accumulator vs per-branch results); `get_run`/`terminate_run` in run_proxy differ only in method/suffix. Same-commit duplication was flagged on both S5 rounds.

**F7 (CONFIRMED, convention): `launchKindFromBody` re-spells the union** (`runtimeRouter.ts:266-269`). Hand-written `value === "canvas" || value === "service"` beside `controlPlaneGrantFromBody`, which correctly derives from the `CONTROL_PLANE_GRANT_OPTIONS` const array; a kind added to `CaptureLaunchKind` compiles but 400s at the route with no compiler signal.

**F8 (PLAUSIBLE, altitude): the `name → launchFields: {title}` mapping lives in the TS gateway** (`RunManager.ts:293`). Functional end to end (generic `launchFields` pass-through exists and `addon_runtime.py:213` reads `title`), but it is a domain key composed in the dumb executor; the continuation precedent builds lineage launch fields Python-side in `capture_rpc_routes.py`, and this mapping belongs there with a typed field.

Nits (no JSON entries): `createWithDisposition` shadows boolean `created` with a `PendingCreate` named `created`; the gateway fingerprint includes presentation fields (cols/rows/oscColorReplies), so a canvas continuation retry after a pane resize now 409s where main replayed — arguably stricter-correct, worth an owner glance; `run_lifecycle_binding_workspace(binding: object)` getattr-typing defeats checking at all four call sites; launch's replay tail re-derives `first_prompt="skipped"` a second way (`model_copy` at `service.py:320` vs the creation ternary); `Mapping[str, Any]` in `run_lifecycle_workspace` carries no why-comment (mirrors existing neighbors); service.py lands at 697/700, the third slice in a row parking a file within a dozen lines of the hard cap.

## Refuted candidates (recorded so they are not re-raised)

- **"`except GatewayUnavailableError, GatewayResponseError:` is a Python-2 SyntaxError"** — raised independently by four finder agents, all of which parsed with an ambient non-repo Python. REFUTED firsthand: the repo interpreter is 3.14.5, PEP 758 makes unparenthesized multi-except valid, `ast.parse` under `api/.venv/bin/python` succeeds, and ruff/mypy/2101 pytest all pass. The identical style ships on main (`run_proxy.py`, `self_reap.py`).
- **Interrupt reports `failed/run_settling` when the interrupt itself worked** — REFUTED: `isSettling`/`isRunning` track process teardown, not harness turn state; Esc cannot exit the PTY process, so the post-settle guard only trips on a genuinely concurrent terminate.
- **stop/interrupt fail-closed when the activity read blips** — deliberate parity with prompt's workspace-visibility gate; receipts say `failed/busy_gateway` honestly and retry succeeds.
- **Readiness should ride the Activity projection instead of `get_run`** — REFUTED by the acceptance criterion itself: gateway-authoritative RUNNING was the adjudicated choice precisely to avoid gating on the laggy projection plane.
- **Migration coverage lost with `test_migrate.py` deletions** — nothing lost: the 110-line smoke moved to `test_migration_roundtrip.py` (extended to 0015) and the backfill/meta tests remain.
