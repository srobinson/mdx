## Quality Map
- Duplication / parallel implementation: `api/src/transport_matters/storage/base.py` `http_error_status` and `api/src/transport_matters/codex/protocol.py` `is_codex_model_rejection` currently expose two parts of the same exchange refusal fact to different consumers. Adding a third frame scan inside `captured_turn` would duplicate the certified predicate. One exchange refusal reader must compose the existing HTTP encoding and Codex classifier, then both fast fail and live status must reuse the same structured extraction.
- Duplication / parallel implementation: scratch `compare_cells.py` `_cells` duplicates `baseline_store` pointer parsing and omits its safety checks. The port must call a new public enumerator implemented inside `baseline_store`, never retain the direct path walk.
- Duplication / parallel implementation: `api/src/transport_matters/baseline_harvest.py` `_comparison_diagnostics` is the only existing structure and content formatter. Productising the comparator requires promoting and sharing it, not a second formatter with drifting vocabulary.
- Boundary / design issue: `api/src/transport_matters/captured_turn.py` `_wait_for_correlated_exchange` already has the validated transport on the matched exchange, but consults only the lossy index summary. The provider neutral wait should consume one refusal value containing status and optional reason. Codex structure remains owned by `codex.protocol`; adapters must not import storage.
- Boundary / design issue: `api/src/transport_matters/harnesses/access_verification.py` `_verify_harness` is the other production consumer of `run_captured_turn`. It catches every fast fail and returns `inconclusive` before `_recorded_outcome`, so a provider access recorder can persist a fresh unavailable reason and the shared fast fail can hide it. The slice must read back a recorded outcome after a refusal and return it when conclusive.
- Boundary / design issue: `api/src/transport_matters/codex/exchange.py` `persist_codex_handshake_failure` persists upgrade status and a synthetic `transport.handshake_failure` request, but that request contains no delivered prompt. The matched delivery fix cannot cover a 401 or 403 upgrade refusal. Scanning arbitrary unmatched run errors would be unsafe because housekeeping can share a run; handshake fast fail needs its own ownership rule over the synthetic marker and `request_kind`.
- Boundary / design issue: `api/src/transport_matters/request_schema.py` `compare_request_schema` is directional. A read only probe at this head produced `BREAKING` for a property removal and `DEGRADED` for the reverse addition. The scratch script feeds one lexically selected direction into an unordered pair bucket, so renaming or reordering models can change the reported severity. A product command must preserve both directed reports and define a reversal invariant summary.
- Boundary / design issue: `api/src/transport_matters/baseline_evidence.py` `BaselineCell` exposes all capture coordinates, but scratch `compare_cells.py` checks only the harness and provider directories. Comparing different harness versions, prompts, permission plans, isolation plans, or runtime templates can mislabel another axis as model dependence. Mixed source commits should be displayed as provenance; the existing same cell contract does not treat source commit as a capture coordinate.
- Dead code / obsolete path: `api/src/transport_matters/captured_turn.py` `_wait_for_correlated_exchange` fast fail is unreachable for the Codex transport it most needs. The repository interpreter confirmed `http_error_status(ResStats(stop_reason="ws_close_1006"))` returns `None`, while the already persisted server frame passes `is_codex_model_rejection` and carries status 400 plus the exact sentence.
- Dead code / obsolete path: `api/src/transport_matters/baseline_evidence.py` `AbaAnalysis.model_dependence_assessed` and `BaselineBundle.model_dependence_assessed` are both fixed to `Literal[False]`; exact searches found no production reader. The reporting command should not create a second persisted model dependence flag. Defer removal to an artifact schema cleanup because the requested port is report only.
- Grooming recommendation: refactor first. `api/src/transport_matters/test_baseline_capture.py` is 861 lines, above the hard 700 line limit, and `_install_capture_fakes` is itself over 150 lines. Move the captured turn fixtures and correlation tests into a focused `test_captured_turn.py` or shared public test support before adding the regression. Production candidates are below the limit: `captured_turn.py` 294, `storage/base.py` 381, `codex/protocol.py` 434, `baseline_store.py` 166, `baseline_harvest.py` 205, `request_schema.py` 581, and `baseline_evidence.py` 617. Avoid adding comparator logic to the last two; reuse their public functions.
