How this behaves on incremental harnesses (codex) Advanced · fine-grained control
Design notes. The optimize decision is one toggle, not a flow. Screen 00 has two states: the gate state (pre-enable) is reveal-first, the per-run token disclosure above a single required "Enable optimization" switch, the strong variant where TM cannot operate until the override is enabled; the operating state (post-enable) shows savings and the evidence link. The optimization is precomputed per harness release version, so flipping the switch applies instantly with no optimizer-running state and no runtime model call implied. The toggle sits in a labeled list that ships with exactly one row in v1, leaving room for future optimization toggles without a redesign. The preferred-agent choice stays a one-time onboarding panel, decoupled from the gate and never blocking it. The end state hands off to 03 for evidence and 04 for edge cases; the full editor remains a labeled side door.
