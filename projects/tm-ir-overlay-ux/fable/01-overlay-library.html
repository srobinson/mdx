Overlays

curate the IR once · native wire regenerated per provider

An overlay is a named, scoped bundle of IR edits, applied automatically and never blocking a turn. Application depends on wire shape, so each overlay reports per fingerprint (harness · version · model): full-context harnesses apply every turn, incremental ones apply when their targets cross the wire. Token numbers are always per run; the reveal lives on Reveal & optimize.

Application semantics

Applied at intercept on every captured run in scope. A turn whose wire payload carries none of the targeted sections is a recorded no-op, never an error.

Need to hand-tune individual IR fields? Advanced · fine-grained control — a power-user surface, not the primary path.

Design notes. Reworked per Stuart's framing: the application profile is a dynamic vertical list, one row per harness · version · model fingerprint, sorted by recency of traffic. Two fingerprints read as two quiet rows; twenty read as a scrollable list behind a "+ N more" expander, so the layout survives 10x providers without a redesign. There is no N-way token comparison matrix anywhere: per-overlay numbers are per applied turn, and the token reveal is always per run, on screen 00. Drafts keep their separate lifecycle section; the enable switch exists only on confirmed overlays. The optimizer-born overlay records its provenance (preference used) alongside breakpoint-born and hand-authored ones.
